Could a skill prevent this?

Yes—especially for recurring process failures. A skill will not eliminate genuine bugs, but it can reduce the need for repeated corrective messaging by making constraints and closeout checks executable parts of the workflow.

Recurring failure Better future skill behavior
Premature “fixed” claims Require evidence before closeout: focused test, affected app build, live browser check where UX changed, and explicit residual-risk statement.
Worktree/in-branch violations Read branch/workspace constraints first, assert the current checkout, and refuse to create or use a worktree when the task says in-branch.
Container-vs-host confusion Classify every endpoint as host, container, LAN, or Tailnet before changing seed/bootstrap commands; verify from the same network namespace as the failing process.
Repeated browser regressions After a UI fix, run a browser acceptance slice against the live app, capture the URL, console errors, and key visual/route assertions before reporting completion.
Long debugging loops Maintain an incident ledger: symptom, hypothesis, test, result, next action, and resolution status. Do not restart from a summary without rechecking the live state.

Recommended implementation: a reusable “harness closeout and constraint ledger” skill composed from systematic debugging, verification-before-completion, frontend testing, and the repository’s stack-verification workflow. It should be applied before implementation begins and again before any “fixed” response.

Interpretation

Primary trigger

Repeated failure after an earlier fix was declared complete, especially when the agent did not verify the live stack or browser state.

Escalation method

Shorter commands, explicit constraints, “check again,” direct log/browser requests, and narrowed scope.

Emotional ceiling

The reviewed records do not show a transition into insults, profanity, threats, or sustained personal attack.

Most useful intervention

Make the agent prove the fix in the affected execution environment before it declares completion. This directly targets the pattern that produces “still broken” and “check again” messages.
