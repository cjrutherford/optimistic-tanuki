Program directive. app-configurator is the internal configuration control plane. Business-site and the future Configurator Workspace are separate self-service products. A workspace owner can configure and publish only their own business site or community; clients, members, and moderators operate only inside explicit membership and permission boundaries. Product services retain their own data and workflows.

Non-negotiable architecture

Control planeConfiguration owns placement, enablement, navigation, theme, policy, release state, and references. It does not own products, posts, threads, or orders.
Product boundariesBusiness, social, store, forum, and blogging services remain authoritative for domain records and validation. Plugins integrate them through narrow data-access adapters.
Self-service safetyPublic landing CTAs begin verified onboarding. The internal TCP configuration service is never a public browser endpoint.

The two flows that govern the whole program

Request isolation
session → authenticated profile → app scope → workspace membership / target → capability permission → domain-record ownership
                                        ✕ deny at the first missing link

Self-service lifecycle
discover → register / sign in → verify → create or claim workspace → owner policy + default config → configure → preview → publish
                                                                     └─ invite / approve / suspend client or member → moderate → audit

Program guardrails

Keep entry points first class. Business-site owner/client routes, community moderation, store management, forum participation, and blogging authoring remain product journeys. The Configurator Workspace composes capabilities and deep-links to their product editors; it does not clone them.
Isolation is more than x-ot-appscope. App scope chooses a permission vocabulary. The server must resolve and authorize a workspace target and its domain record on every protected request, query, cache key, event, and background action.
