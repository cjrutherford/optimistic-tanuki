# S3 receipt retention foundation — incomplete

2026-11-04. Receipt cleanup is **not implemented** and receipts remain unbounded. This is not S3 acceptance.

Directory reconciliation now acquires a transaction-scoped, event-namespaced PostgreSQL advisory lock before its existing community lock. This establishes the lock order for future event operations; it does not itself authorize deletion or prevent a stale delivery after deletion. Existing receipt replay behavior is unchanged. Advisory hash collisions can cause extra serialization.

A disposable PostGIS 17 database was migrated using `directory:typeorm:migration:run`, then `NX_DAEMON=false NX_ISOLATE_PLUGINS=false NX_NO_CLOUD=true pnpm exec nx test directory --skip-nx-cache` ran in `s3live-directory-builder:latest` with current Directory source, tests and migrations mounted. The new real-PostgreSQL barrier test passed: a separate transaction could not acquire the event lock while apply was paused, could acquire it after commit, and a mismatched community replay failed. The suite reported 16 passed, 1 failed, 1 skipped. The failure was the unrelated migration-retry test: the builder image did not contain `apps/directory/migrate-with-retry.sh`, which was not mounted for this run. Log: `/tmp/s3-retention-lock-check.log`. The disposable container and network were removed.

Required subsequent work: an authenticated Social exact-event membership operation returning the current snapshot for pending events, authoritative absence separately from mismatched identity and errors; event-then-community locking for apply and event locking for cleanup; fail-closed cleanup and a retired response without projection writes or attestations; a cleanup driver and PostgreSQL pause-barrier tests for apply/cleanup races, delayed duplicates, outage, mismatch, replay and lost ACK. A Social ACK may race cleanup and leave a safe orphan. A hard cap and event epochs/nonces with restore fencing are also required; revision plus community UUID alone makes no restore or epoch safety claim. No TTL or highest-sequence cursor is justified. Geometry remains pending, and no provider, POC data, paid operation or publication was involved.

## Exact membership fence (implementation in progress)

Directory now takes the per-event transaction lock before checking a receipt and, when none exists, queries an authenticated Social exact-revision membership RPC under the event and community locks. Social reads the outbox identity and eligible current snapshot in one database statement; a different community for a retained revision is an error. An absent event returns retired without a receipt or town mutation. A bounded sweep checks each receipt under the same event lock and deletes only after Social reports absence; failures retain it. The worker treats a retired response as terminal and does not acknowledge it. No TTL or high-water mark is used.

The Social outbox hard cap remains a backpressure and availability limit. Independent database restore, rollback, or revision reuse requires an epoch/restore protocol before deployment; this implementation does not establish one. S3 is not complete: the membership RPC and the cleanup/response races still require end-to-end real-Social PostgreSQL evidence, including unavailable and mismatched identities, and the build/test results must be evaluated. The test fixture's delayed request uses simulated Social membership and is not that evidence.

A fresh isolated PostGIS database and the existing `s3live-directory-builder:latest` image ran the Directory migration and uncached Nx Directory test target with the entire current `apps/directory` mounted, including `migrate-with-retry.sh`. The previously missing script test passed; 18 tests passed and one unrelated Social-seed integration case was skipped. This is a corrected test invocation, not a rebuilt image or complete S3 validation.

The current mounted sources also passed uncached Nx development builds for `social`, `directory`, and `directory-worker` in the existing respective builder images. These builds do not prove RPC interoperability or the required real-Social races.
