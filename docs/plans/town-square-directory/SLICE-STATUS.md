## Local Town Square integration continuation

The user redirected the objective to a running directory in the local development stack, with public deployment deferred to their later decision. A separately credentialed, explicitly enabled local evaluation path now reads completed non-revoked private projections, checks current town eligibility before and after reading, forwards a bounded page through the gateway and displays listing names, categories and source notices on the town page. It supports additional pages and strips coordinates at the gateway. This is not the public release path: source policy/classifier authority, verified town assignment, real data loading, end-to-end stack/browser verification and operational deletion remain open. Do not claim the local directory is running on this evidence.

The local `ot_gateway` and `ot_local_hub` containers were started without recreating the shared PostgreSQL or Redis containers. Gateway health is green and the Town Square root returned HTTP 200. The local listing route currently returns 503 because Directory is not yet running; no source records have been loaded. Do not confuse running shells or the synthetic browser check with a working directory.

The local integration was initially started against an **isolated snapshot** of `ot_social`; the later cutover below switched it to the original source. Directory completed registration of 261 eligible towns. The Valdosta local endpoint returned one actual listing from the checksum-pinned September POC file after an independent check against Walmart's public store page, with Meta/CDLA source attribution; the rendered Town Square page displayed it and labeled its POC town assignment unverified. This proves one local vertical path only. It is not the requested October acquisition or a complete directory, and the original Social database has not been activated for ongoing Directory capture. The local Social schema received additive Directory migrations after a restricted backup; the shared PostgreSQL image lacks PostGIS, so Directory uses a separate PostGIS container.

On 2026-11-09 the local services were switched from the temporary Social snapshot to the original local `ot_social` source. Registration reached `reg-running` with 261 eligible towns and the existing Valdosta listing search returned HTTP 200. A temporary host-access fence was used for the cutover and PostgreSQL access rules were restored. This is local evidence only; direct SQL writes, restore fencing and production activation remain separate limitations. The current served candidates are the screened September POC subset; the October release is still staging.
