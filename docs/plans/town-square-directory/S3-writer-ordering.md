# S3 Social writer ordering evidence — 2026-11-05

A fresh disposable PostGIS 17 database was migrated with the Social Nx target. The focused PostgreSQL test uses the real `CommunityService.update` and `delete` methods and real TypeORM community/register writes; identity and authorization reads are stubbed. It pauses one transaction after its community write and before register recording, then starts the competing service operation.

- Update held before register recording, then delete started: PostgreSQL reported the competing transaction blocked by the first transaction's backend PID; after release both completed and the community was absent with a `deleted` register tombstone.
- Delete held before register recording, then an update using a previously loaded entity started: PostgreSQL reported the update blocked by the delete backend, then after deletion committed the update failed with not-null violation `23502`, and the community remained absent with a `deleted` register tombstone.

The focused Nx test passed 2/2. An intermediate run failed because the temporary database container had disappeared; a new disposable database was migrated and the final test passed. These are controlled interleavings for two Social service paths in inactive mode without a source authority row. The test checks PostgreSQL blocking PIDs, but does not independently inspect the exact lock type or normal service dependency wiring; it does not cover every writer, direct SQL, import, long-running transaction, process crash, active mode, authority fencing, consumer, recovery, or privacy delivery. The global source epoch advisory lock is taken before the relevant service writes; direct writers that bypass it are outside this proof. External fencing and existing Directory startup/ACK restrictions remain required. No provider call or public release was made.
