# S3 Social source register reads — 2026-11-05

Social exposes separate internal TCP scan and exact-token read commands using `DIRECTORY_REGISTER_READ_SECRET`. The secret must be at least 32 bytes and differ from the existing Social delivery, eligibility, recovery-read and receipt-signing credentials. An authenticated request still needs the current source epoch and a locally valid, unbound capture-only authority. The handlers do not clear dirty rows, authorize Directory or enable public serving.

Scans return at most 200 dirty community IDs, tokens and operations in UUID keyset order. A client must repeat scans from the beginning because a live page is not a point-in-time census and changes behind a cursor can be missed during one pass. Exact-token reads distinguish a superseded identity from a current record. A current deleted, private, wrong-scope, non-town or missing community returns a null snapshot; eligible public Local Hub cities/towns return only ID, name, slug, administrative area and eligibility fields. Invalid persisted operations fail rather than being treated as deletion. The authority row is locked inside a Social transaction; the service wrapper limits lock waits to two seconds and individual statements to five seconds.

Focused evidence: the pure read unit suite passed 8 tests; a fully migrated disposable Social/PostGIS database passed 4 tests covering actual eligible/private/wrong-scope rows, superseded token after a real privacy change, recovery waiting for the read authority lock, and a bounded lock timeout. The RPC authentication unit suite passed 3 tests. A separate temporary built Social server and Nest TCP client on an isolated port denied a wrong synthetic credential, scanned two synthetic towns and returned the public town projection plus a null private snapshot. That wire-level test preceded the timeout-wrapper change; the wrapper was subsequently tested against PostgreSQL and Social development build passed. A read-only independent review found no concrete blocker but identified pagination, locking and source/Directory authority limits; the RPC lock timeout and actual mutation-supersession evidence were added in response. It did not run tests.

Current source epoch and local locks cannot detect a restored database with an old valid epoch, prove a current Directory peer, or cover direct writers that bypass capture. The transport credential is an internal service secret, not a substitute for network isolation or a production credential provisioning procedure. Response snapshots may become stale immediately after the Social transaction ends. No worker is connected to these commands; no destructive acknowledgement or production startup guard was lifted. Directory reconciliation, missed-event repair, durable queue dispatch, two-store fencing/restore and the user-selected 15-minute SLO remain unproven.
