# S10 owner decisions (2026-11-18)

The owner made these decisions directly when S10 implementation started. They replace the matching "Decisions for the owner" items in the [S10 acceptance scorecard](S10-acceptance-scorecard.md).

| #   | Topic                   | Decision                                                                                                                                                                                                                                                                                 |
| --- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Acquisition             | **Overture, automatic.** Acquisition is authorized for Overture only. A worker acquires each eligible town from the pinned Overture release under the rights policy, the budget ledger and the kill switch. New towns fill without an operator. Every other provider stays unauthorized. |
| D2  | Geometry                | **Automatic from Census TIGER.** Each town is matched to its TIGER place (or county subdivision) automatically. A single unambiguous match is installed as the town's geometry. Ambiguous or missing matches go to the existing boundary review queue.                                   |
| D3  | Standalone AllThePlaces | **Implement.** AllThePlaces gets its own provider wiring under CC0, separate from the copy carried inside Overture.                                                                                                                                                                      |
| D4  | Geoapify                | **Implement as private enrichment only.** It stays denied for public display and export.                                                                                                                                                                                                 |
| D5  | Remaining deferrals     | `/regions` and the fixture/sample provider modes stay deferred in [DF-008](../../release-readiness/DEFERRED-FEATURES.md).                                                                                                                                                                |
| D6  | Shared-UI regression    | **Bring up the full stack.** Start the missing services (forum, chat, OAuth), register business-site, and rerun client-interface, forgeofwill and business-site until they are clean or the remaining failures are real regressions.                                                     |

## Second round (2026-11-18, after implementation)

| #   | Topic                     | Decision                                                                                                                                                                                                             |
| --- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D7  | Towns with no TIGER match | **Improve the matching rule** (name variants such as "city of" and abbreviations, nearby reference points) and rerun. Whatever is still unclear stays in the review queue.                                           |

| D11 | Address auto-approval     | **Auto-approve strong matches only:** the address and map point are both inside the town's verified boundary and the sources agree. Everything else waits for a reviewer. The owner account holds the reviewer role. |
| D12 | Pilot rows (4,850)        | **Replace with fresh data.** Retire the pilot rows; the pilot towns are refilled by automatic Overture and AllThePlaces runs, which record their source.                                                             |
| D13 | Uncertain duplicates      | **Hide the weaker listing** (the less well-sourced one) and queue the pair for review. A reviewer can restore it.                                                                                                    |
| D14 | Technical rows            | **Generate OpenAPI documentation** for the directory endpoints. A separate normalize stage was not chosen; that ledger row stays open.                                                                               |

## Outcomes on the local stack

- D7: 236 towns have installed geometry. 26 are still unmatched, and some of those have no TIGER entity at all.
- D8: Geoapify is live with a 2,500-cent monthly ledger. The per-request price is unverified; the ledger assumes 1 cent per lookup.
- D9 and D12: all 261 towns answer the public listings route. Legacy pilot scans are swapped out as each fresh scan completes, with 32 towns left at the last check.
- D11: deployed, but no refresh has run since, so nothing has been auto-approved yet.
- D13: the worker queued more than 6,500 duplicate cases. Part of that volume comes from towns that serve old and fresh scans until the swap. Review works through the gateway route; the Owner Console screen for it is not built.
