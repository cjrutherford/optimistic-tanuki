# S3 Social authority schema and legacy activation fence

Social's epoch row now carries nullable activation and owner UUIDs, a Social generation defaulting to zero, a nullable Directory generation, and a phase defaulting to `fenced`. Existing epoch and outbox data are retained. The old three-field recovery proof cannot activate Social: both the service function and the operator command fail explicitly before changing authority or retiring events. No cross-store transition is implemented.

The added phase marks upgraded rows as legacy; it does not rewrite the pre-existing `fenced` boolean. Live Social reads, writes and the v2 ACK primitive require an active phase, an unfenced boolean, and a complete v2 identity with positive generations. Fenced recovery reads require both fence representations to agree. Existing processes still require an external fence during an upgrade. Do not treat this schema as a complete recovery or activation protocol.

Verification: the Social Nx migration target ran against fresh and seeded upgrade disposable PostGIS databases; the seeded upgrade retained its pending outbox row and defaulted the new authority fields. The isolated PostGIS activation suite exercises fresh and upgrade defaults, outbox retention, and rejection of a valid bound legacy proof. Migration validation and the Social build were run. These checks do not establish cross-store recovery or live deployment readiness.

Compatibility verification: an isolated PostGIS test applies the Social authority schema migration to a legacy `fenced=false` row and confirms live writes, snapshot, membership, census, unread, eligibility and a correctly signed v2 ACK are rejected, while geometry and the outbox are unchanged. A separate PostGIS ACK test exercises a deliberately complete active test identity. No activation or startup gate was enabled. The migration regression applies the authority migration to a representative pre-upgrade fixture, not the complete migration chain.

Account-export disposition verification: the five authority columns are excluded as singleton operational recovery state. The full Social Nx suite passed 53 suites and 597 tests, with 9 suites and 25 tests skipped. The disposition PostGIS test passed separately (1 test, no skips) against a disposable database with the complete Social migration chain: 36 entities, one junction, 38 application tables and 341 columns. Extension-owned PostGIS catalog objects are excluded from the application table count.
