# Social prepared attestation

The operator must independently establish and maintain the external fence over all Social writers, Directory instances and workers; the confirmation flag is an assertion, not a fence. Bind the exact six-field recovery identity and provide the v2 signed traversal proof on stdin. `prepare --confirm-external-fence` accepts the same identity arguments as `bind`. Configure `DIRECTORY_RECOVERY_PROOF_SECRET`, `SOCIAL_OPERATOR_PRIVATE_KEY_FILE`, `SOCIAL_OPERATOR_PUBLIC_KEY_FILE`, `DIRECTORY_OPERATOR_PUBLIC_KEY_FILE`, `SOCIAL_OPERATOR_KEY_ID`, and `DIRECTORY_OPERATOR_KEY_ID` in the operator environment. Private key files should be readable only by the operator. Keys must be distinct Ed25519 keys and IDs. The private key remains in the operator process; it is never sent to a worker. Protect stdout as an operator artifact.

The transaction locks and checks the identity and fence, retires the baseline, and stores the retirement count and SHA-256 digest and the attestation prerequisite. The retirement digest hashes JSON of an array consisting of `social-retirement-v1` followed by revision-sorted arrays of revision, community ID, operation, source epoch and event nonce. The traversal digest hashes JSON of the ordered array `social-traversal-v2`, source epoch, recovery epoch, owner, activation ID, Social generation, Directory generation, traversal marker and proof signature. The CLI signs the persisted prerequisite after commit. A crash before signing can be retried under the same external fence and proof; retry returns the stored result and does not retire subsequent events. A legacy prepared row without the payload fails closed and requires a new fenced recovery. The digest is an audit commitment, not proof that the external fence exists.

This slice does not enable Directory, ACK, startup, or public serving. Full cross-service activation, external fence enforcement, production key custody, and operational recovery remain outside its evidence.
