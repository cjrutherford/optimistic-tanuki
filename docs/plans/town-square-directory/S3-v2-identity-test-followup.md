# S3 v2 identity test follow-up

The existing PostGIS reconciliation, receipt-capacity, and worker census/delivery tests now use complete v2 identities (revision, community ID, stable event nonce, source epoch, recovery epoch) and a durable blocked recovery authority. Their membership fixtures return the corresponding epoch and nonce. Existing concurrency, replay, transaction-visibility, retirement, privacy-withdrawal, durable-cursor and late-insertion scenarios remain. The periodic census does not certify recovery. These tests use synthetic membership sources; they do not prove cross-service recovery or authorization to start or ACK.

## Evidence (disposable local PostGIS and Redis)

- Fresh Social and Directory Nx migration targets succeeded on PostGIS 17/3.5; Directory requires explicit `DIRECTORY_RECEIPT_CAPACITY` (the first attempt without it failed as designed). Directory receipt-slot upgrade test: 1 passed, 0 skipped, including concurrent legacy writer blocking and rollback. This is not a full legacy Social/Directory identity upgrade proof.
- Reconciliation test: 4 passed, 0 skipped on PostGIS with a 100-slot pool. Receipt-capacity test: 1 passed, 0 skipped on a separate two-slot database. Worker census test: 4 passed within the full worker run on a 100-slot database.
- Full `directory-worker:test` with disposable credentialed Redis, ACL workload, AOF recovery and process-restart flags: 20 passed, 2 failed, 0 skipped. One failure was test setup: Redis URL used `test-a`, while the ACL fault test modifies `s1test-a`; after correcting the disposable ACL username, the queue test alone passed 10/10. The other was the existing worker process restart test: it expects readiness 200, but the process exits at the restore startup fence. No bypass was added; actual worker reconnect after startup remains unproven.
- Full `directory:test` with a shared migrated database: 18 passed, 6 failed, 6 skipped. Its parallel fixtures compete over the singleton recovery authority and require incompatible 2-, 10-, and 100-slot pool sizes; the first failed setup also left the shared connection initialized, causing follow-on failures. Skips were fresh/upgraded Social nonce immutability, recovery authority, legacy identity upgrade, fresh identity chain, and seeded/non-seed Social UUID integration. Separate disposable runs subsequently passed recovery authority (1/1) and fresh nonce/identity (2 passed, 2 skipped: upgraded nonce and legacy identity upgrade). The legacy identity upgrade and seeded UUID integration remain unverified.
- Social Nx test run with `SOCIAL_EPOCH_TEST=disposable-epoch`: 48 suites passed, 6 skipped; 591 tests passed, 11 skipped. The PostGIS epoch suite included eligible and private/ineligible snapshots, membership privacy, nonce collisions, stale epochs and locking. A second run with `SOCIAL_OUTBOX_TEST=disposable-s3fresh`: 48 suites passed, 7 skipped; 588 tests passed, 16 skipped, including the real PostGIS outbox suite. Nx forwarded the intended path filter incorrectly and ran broader suites; counts are for each entire run.
- `pnpm run validate:typeorm-migrations` passed. `pnpm nx run-many -t build -p directory directory-worker social --parallel=2 --skip-nx-cache` passed with `NX_DAEMON=false NX_ISOLATE_PLUGINS=false`.

No full recovery, production readiness, or end-to-end delivery/ACK claim follows. Startup and ACK fences must remain authoritative. No provider calls, POC data, paid operation, publication, production operation or commit was performed.
