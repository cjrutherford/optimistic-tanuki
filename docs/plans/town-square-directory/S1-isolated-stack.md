## Results

- The checked-in directory Compose file plus a temporary override started services before migration. Both readiness endpoints returned HTTP 503; explicit `directory:typeorm:migration:run` succeeded with the dedicated role, then both returned HTTP 200. A second migration run reported `No migrations are pending`. Compose itself does not order migrations before app startup.
- Redis used AOF with `appendfsync always`; default user disabled. The test user was restricted to `~s1isolated:jobs-v3` and `PING`, `CLIENT SETINFO`, `EVAL`, `HGET`, `HLEN`, `HEXISTS`, `HGETALL`, `HSET`, `HDEL`. Both services became ready with this ACL. PING and hash write succeeded; GET, access to an unrelated key, and CONFIG returned `NOPERM`. This is an exercised candidate ACL, not proof of every queue transition or a production ACL review.
- A synthetic completed-job-shaped marker in the queue hash survived a Redis restart and a clean-stop AOF volume archive copied into a separate Redis container and volume. A PostgreSQL custom-format `pg_dump` restored into a separate database on the same disposable server and retained a test installation row. The directory API and worker both became ready after Redis and application restarts, and the original database retained the row. This does not prove power-loss durability, point-in-time recovery, off-host backup, a restored worker consuming a job, or a production runbook.
- Recreated the worker with the locally present older `directory-directory-worker:latest` image `sha256:a489c72f7e9470598ba159edc09ba2a12315d52b5d5ee33c8b9f5362228386a9`, then the current image; each became ready with the same database and Redis data.
