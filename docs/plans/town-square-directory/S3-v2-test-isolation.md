# S3 v2 test isolation

The Directory Nx test target clones the migrated `DIRECTORY_TEST_DATABASE_URL` template into a disposable database for each test file. Files run sequentially; concurrency exercised inside each test is unchanged. Each clone starts with an empty receipt pool so tests can independently choose its fixed capacity. The runner removes each clone even when its tests fail. A template containing receipts is rejected. The PostgreSQL user needs CREATE DATABASE and permission to clone the template, which must be idle and dedicated to tests. The recovery and migration test URLs are redirected to the clone when they equal the template URL; other explicitly supplied URLs remain caller-owned. Without the main test URL, the normal tests run with database-dependent cases skipped.

The worker startup test checks the restore fence and failure to start. The Redis restart scenario remains opt-in via `DIRECTORY_WORKER_RESTART_TEST=1` for the operational v2 implementation; it must not be enabled while startup is fenced. The queue ACL test mutates the user supplied by the test URL, so that user must be disposable.

Verification on 2026-11-04 used disposable PostGIS 17-3.5 and Redis ACL containers, with the Directory migration chain applied to a fresh template. `NX_DAEMON=false NX_ISOLATE_PLUGINS=false pnpm nx run directory:test --skip-nx-cache` passed 25 tests, skipped 5: two Social nonce database variants, two Social/Directory identity migration fixtures, and Social seed fixtures were not provisioned. Recovery authority and receipt migration URLs pointed to the template and were cloned. `pnpm nx run directory-worker:test --skip-nx-cache` passed 22, skipped the fenced operational restart case; Redis ACL workload and AOF recovery were enabled. Worker census tests require a fresh disposable database for each suite run; they leave fixture state behind.
