# S1 worker Redis restart recovery

The worker queue reconnects after a previously established Redis connection is lost. Commands fail promptly while disconnected; the worker loop retries, and queue leases handle claims whose outcome is uncertain. Initial connection failure still fails startup. Readiness checks the real database and Redis dependencies.

On 2026-11-04, the full `directory-worker:test` Nx target passed with 13 tests, 0 failures and 0 skips (6.7 seconds of test execution). The run used a disposable local Redis container with separate `s1test-a` and `s1test-b` users restricted to their own key prefixes and queue commands, plus an admin connection solely for ACL fault injection. All three Docker integration flags were enabled: `DIRECTORY_ACL_WORKLOAD_TEST=1`, `DIRECTORY_RECOVERY_TEST=1`, and `DIRECTORY_WORKER_RESTART_TEST=1`. The worker restart test separately created disposable Redis and PostGIS containers. Its Redis user had only the candidate ACL commands and its exact queue key; its PostgreSQL login was a non-superuser with database connect permission, used for the minimal readiness fixture.

The actual worker process observed readiness 200, then 503 after its Redis container stopped, then 200 after that same container restarted on the same loopback port. The PID remained unchanged, and that worker completed a newly queued job after recovery. The ACL workload also checked denial of foreign keys and unrelated commands. The AOF, crash, lease and lost-reply integration test passed. All containers were uniquely named and removed; no S1 test containers remained after the run. This controlled restart does not establish failover, long-partition, power-loss, or exactly-once guarantees, nor validate deployment configuration.

The test target now fails immediately with a list of missing `DIRECTORY_TEST_REDIS_URL`, `DIRECTORY_TEST_REDIS_URL_B`, and `DIRECTORY_TEST_REDIS_ADMIN_URL` variables, instead of implicitly connecting to localhost and retrying forever. The candidate ACL Docker workload is opt-in; the restart and AOF tests remain opt-in. A 180-second outer deadline bounds the test command. With all three URLs unset, the Nx target was verified to fail with the missing-variable message, 1 failed test file and 3 skipped integration tests, in approximately 0.54 seconds of test execution. Invalid or unresponsive configured services can still consume time up to the target deadline.

Verification used `NX_DAEMON=false NX_ISOLATE_PLUGINS=false` and `pnpm nx test directory-worker --skip-nx-cache` through the cached pnpm 11.0.9 `pnpm.mjs` entry point, with a 200-second outer process deadline. The system Corepack shim failed before Nx with `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`; the cached pnpm entry point succeeded. Nx initially reported a flaky task after the deliberate missing-configuration failure, and the final configured run passed without that warning. No production services, provider calls, imported sources, or paid operations were used. The existing build pass and prior default-Redis process recovery were recorded before this verification; no new build was run for these test-only changes.
