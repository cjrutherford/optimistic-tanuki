# Final Social activation

The operator must establish and maintain an external fence over all Social writers, Directory instances, workers and serving for the whole operation and any retry. The confirmation flag is an assertion, not a mechanism that enforces that fence. Run the Social `source-epoch-operator activate-final --confirm-external-fence <sourceEpoch> <recoveryEpoch> <owner> <activationId> <socialGeneration> <directoryGeneration>` with JSON on stdin of the form `{"prepared": <Social prepared attestation>, "enabled": <Directory enabled attestation>}`. Set `SOCIAL_DATABASE_URL`, `DIRECTORY_DATABASE_URL`, `SOCIAL_OPERATOR_PUBLIC_KEY_FILE`, `DIRECTORY_OPERATOR_PUBLIC_KEY_FILE`, `SOCIAL_OPERATOR_KEY_ID`, and `DIRECTORY_OPERATOR_KEY_ID`. The operator needs no private keys. Protect the proof bundle and database credentials.

The operator locks Directory's recovery authority and current enabled checkpoint before locking Social's authority, with bounded connection, statement and lock waits. It verifies both distinct-key Ed25519 envelopes, the complete recovery identity, the Directory checkpoint and its prepared-envelope digest, and Social's persisted prepared payload. The Social transaction records the enabled envelope's digest and `directory-enabled-v1` version with the retained prepared payload, and changes phase and fence together. An exact active retry checks both stores and both proofs and performs no Social update or event deletion. Old active rows without the recorded payload fail closed. Begin a new fenced recovery if the checkpoint or identity no longer matches; do not use a stale proof.

This is a two-store handoff, not a distributed transaction or proof of the external fence. Directory's lock remains held until Social commits. Concurrent operators serialize; bounded lock waits may require retry under the same fence. Directory and worker startup and ACK remain disabled. This step does not authorize serving, deployment, production key custody or a production recovery.

Local verification used two fresh databases in a disposable PostGIS 17 container, each migrated with its owning Nx migration target. The focused Social Nx test passed (one test): it exercised the real prepare and enable steps, stale checkpoint locking, each identity field, invalid envelopes and reused keys, a trigger-induced rollback before commit, concurrent final calls, exact post-commit retry, later-event preservation, legacy payload rejection, and the operator's fence and output handling. The crash cases are simulated by rollback and retry, not process termination at commit boundaries; external fencing and production operation were not tested. An initially broader Social test invocation also failed the existing account-export disposition inventory check because `CommunityDirectoryEpoch.columns` omits `preparedPayload`.
