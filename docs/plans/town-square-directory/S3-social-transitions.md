# Social local authority transitions

These operator-only operations require the user-approved external fence to stop every Social writer, worker and serving process throughout recovery. A database row cannot detect a restored process or enforce that external fence. Runtime reads, writes and acknowledgements remain fenced; there is no final activation here.

`begin-recovery --confirm-external-fence` creates a new source epoch and activation ID and increments the Social generation under advisory and row locks. `fence` and `rotate` also start a new incarnation. Read the resulting singleton row using operator credentials. For an absent singleton, generation starts at 1. Each subsequent refence invalidates prior identities and proofs. Invalid phases and incomplete active rows fail closed.

Once traversal has completed, the operator obtains the Directory recovery epoch, owner and generation from the fenced Directory authority and a valid traversal proof. `bind` and `prepare` each require `--confirm-external-fence` followed by source epoch, recovery epoch, owner, activation ID, Social generation and Directory generation, in that order; provide the signed traversal proof as JSON on stdin and the distinct `DIRECTORY_RECOVERY_PROOF_SECRET` in the operator environment. Binding records the Directory identity only for the exact Social incarnation. The existing traversal proof authenticates source epoch, recovery epoch and owner; Directory generation is an operator-observed value, not a field authenticated by that proof. Never accept it from an untrusted caller. These commands are not exposed over HTTP.

Preparation verifies the traversal proof and exact six-field bound identity under the row lock, deletes the externally frozen outbox baseline and marks the row prepared in one transaction. An exact prepared retry performs no deletion or update; after refencing, stale identities cannot retire events. Transaction rollback restores both the outbox and phase. Do not release the external fence or interpret preparation as activation. Cross-store activation and runtime/ACK unfencing remain future work.
