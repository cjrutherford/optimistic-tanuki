## Receipt review follow-up: local Compose integration

The `directory` profile is defined in the main Compose file (and therefore its development override) and the standalone local-hub E2E Compose file, using the shared service definitions in `apps/directory/compose.yaml`. It is opt-in; ordinary stacks do not require Directory secrets. Set `DIRECTORY_INTERNAL_URL=http://directory:3120` on the deployment to enable the gateway route. Directory, its receipt endpoint, its worker and its migration job have no published host ports. They use the stack's service network; this does not provide network isolation from other services on that network.

Before enabling the profile, provision a dedicated PostGIS database and database role with only the permissions needed for Directory migrations and runtime, and a Redis endpoint with a dedicated ACL identity and unique queue prefix. Set deployment-wide `DIRECTORY_DATABASE_URL`, `DIRECTORY_REDIS_URL`, and `DIRECTORY_QUEUE_PREFIX`. Supply three distinct, independently generated secrets of at least 32 bytes: `DIRECTORY_SOCIAL_SECRET` (Social, Directory, worker), `DIRECTORY_SERVICE_SECRET` (Directory and worker), and `DIRECTORY_RECEIPT_SIGNING_SECRET` (Directory and Social only). The worker must never receive a Directory database credential or the signing secret. Do not reuse existing application secrets. The URL and secrets have no usable defaults; missing database configuration makes migration fail, and missing or reused receipt credentials prevent Directory startup.

Run the normal stack's Social migrations first: the main stack's `db-setup` already gates Social. For local-hub E2E, run the Social migration target explicitly against the actual Social database before starting Social or the Directory profile; its optional `db-setup` service alone does not guarantee migrations for the configured `ot_local_hub` database. Provision the dedicated Directory database and PostGIS extension before startup. Then start the stack with `docker compose -f docker-compose.yaml -f docker-compose.dev.yaml --profile directory up -d` or, for local-hub, `docker compose -f docker-compose.local-hub-e2e.yaml --profile directory up -d`. Compose waits for the Directory migration job to complete successfully before starting Directory, then starts the worker. Social must be reachable using its existing `social:3003` service name. These settings apply to the deployment, not individual towns. Never run the local-hub command against an existing shared stack merely to test this feature.

Social's receipt response now reports `deleted` or `already-absent`, both acknowledged outcomes; unknown results fail the worker delivery and are retried. A repository-backed test covers the exact pair, the deletion, and an idempotent retry. The changed contract requires coordinated Social and worker deployment; an old Social response without the result fails closed in a new worker.
