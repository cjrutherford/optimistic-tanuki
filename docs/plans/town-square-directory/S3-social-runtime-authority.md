# S3 Social runtime authority — incomplete local foundation

The startup and ACK RPC fences remain in force. This slice is **not accepted**: the new `lockSocialRuntimeAuthority` helper is not yet wired into normal directory reads, producers, or the ACK primitive. It checks an active, unfenced six-field local identity, the stored accepted Directory-enabled attestation version and digest shape, and an explicitly supplied epoch pair while holding a transaction-scoped Social singleton `FOR SHARE` lock. The attestation was cryptographically verified by the activation path; this check does not independently verify the signature or establish current Directory authority.

Remaining work: establish a trusted expected epoch pair at each normal caller; wire the check inside each affected transaction before business/event locks, including inactive-mode writers and every ACK deletion entry point; preserve the Directory-to-Social order when both stores are involved; and retain the global guards until race-safe peer checks exist. Existing normal-read contracts carry at most the source epoch, and the exported raw ACK deletion helper can bypass the new check. Neither should be treated as runtime authority evidence.

Verification: the focused Nx unit test covers lock query, active/missing/fenced/incomplete authority, malformed or absent accepted digest, and mismatched or absent expected epochs. The Social development Nx build passed. A full migrated PostGIS test of races, rollback and all paths has not been run; no claim of integration or peer safety is made. No schema fields were added.

## Peer-check experiment (2026-11-05; not enabled)

`directory-peer-authority.ts` adds an isolated, unwired transaction primitive. It obtains the Directory shared transaction advisory lock before reading the enabled checkpoint, checks all six identity fields and the installation epoch, then takes the Social shared row lock and requires its previously accepted enabled-attestation digest. The digest is trusted only as the durable result of the existing operator activation verification; Directory does not store the signed envelope or its digest. No epoch comes from a request. The lock is held until after the Social transaction commits, so compliant Directory refences wait while both connections remain alive. The callback must make only transactional Social changes. This is not an endpoint, a deployed client, an authorization to unfence, or a distributed atomic commit.

The Directory connection can fail after its last liveness query and before Social commits; PostgreSQL releases its advisory lock on connection loss. Directory refence can then overlap the in-flight Social transaction. Also, a Directory commit failure after Social commits produces an ambiguous result; blindly retrying a non-idempotent callback is unsafe. A successful check therefore cannot prove safe runtime authority. Every Directory refence must participate in the same advisory lock, and external fencing and drain of in-flight work remain required. Directory restore, failover and arbitrary privileged writes are outside this lock's protection. The existing global startup and ACK RPC fences remain closed.

No credentials or role provisioning were added. A future integration must use a separately provisioned Social-to-Directory read/lock identity, never Directory's write role or operator/signing keys; audit inherited privileges, ownership, superuser and schema access, and reject excessive privileges. The connection must have only the required reads and advisory-lock capability. There is no public route. The experimental helper is not wired to application traffic and must not be treated as enforcing that role.

Verification is incomplete: focused mocked tests cover ordering, mismatches, absent authority and error rollback, but no fully migrated separate PostGIS concurrency, connection-loss, refence, privilege-denial or retry proof has been run for this component. An Nx invocation intended to filter the new spec ran other Social specs as well; the new spec passed, while unrelated existing community/eligibility tests failed. This slice does not satisfy the requested integrated peer check or S3 acceptance.
