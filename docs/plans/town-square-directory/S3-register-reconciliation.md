# S3 register reconciliation — 2026-11-05

The current unconnected Directory prototype takes a source/recovery epoch and exact Social token, holds the Directory recovery-authority and per-town advisory locks, then performs the authoritative Social read inside the Directory transaction. An eligible town is projected as pending with one durable blocked provider-work row; a current null snapshot withdraws eligibility and removes that work. A superseded token does nothing. Repeated application is idempotent at the town/work identity. The register remains dirty; no receipt, acknowledgement or cleanup is implied. This prototype currently checks the Directory **blocked** recovery phase and is not a normal runtime authority.

A focused integration test used separately migrated disposable Social and Directory databases and the actual Social read and Directory reconciliation functions. It verified duplicate replay, the blocked work row, an old token becoming superseded, privacy withdrawal and cancellation, and rejection after the Social source epoch was rotated. It also paused a read after it obtained the public snapshot, made the Social town private, then allowed the Directory transaction to commit. The Directory temporarily retained the old pending projection; subsequent application of the new token withdrew it. This is concrete evidence that an exact read does not make privacy changes atomic across databases. The pending projection is not safe public-serving authority; no public geometry or Directory startup guard was enabled.

The test requires explicitly named disposable databases on loopback and checks that all affected Social and Directory tables are empty before any write. Its connection cleanup is protected even if setup or teardown fails. It can run narrowly via `nx run directory:test-register-pair` with `S3_REGISTER_PAIR_TEST=disposable`, `S3_REGISTER_DIRECTORY_URL` and `S3_REGISTER_SOCIAL_URL` configured. One earlier Nx `exec` invocation unexpectedly executed the test repeatedly due to project graph selection; the disposable fixture was rebuilt and the dedicated target passed. The test uses direct function calls across two databases, not authenticated network transport, a running worker or a full service stack.

Independent source review found no concrete prototype security or privacy regression, but flagged the need for test fixture emptiness checks and connection cleanup; both were addressed. Source-only capture is not bound to the Directory recovery epoch. Authority rotation, town-lock contention, crash/replay, actual authenticated delivery and complete coverage are still unproven.

Validation: Directory Nx build passed, Directory worker Nx build passed after its stale three-field recovery command was replaced by an explicitly fenced six-field traversal command, and the two-store test passed. The Directory suite with isolated migrated clones passed 36 tests and skipped 12; the worker suite with an isolated ACL-configured Redis passed 18 tests and skipped 7. The worker suite initially failed because disposable Redis environment variables were absent; it passed after proper isolated setup. These skips are not S3 acceptance evidence.

Directory startup and legacy ACK remain fenced. Secure consumer binding, exact-token receipt/ACK, durable scheduling, census repair, all-writer coverage, separate source/Directory restore and the selected 15-minute SLO remain unfinished. No provider calls, public release or production changes occurred.
