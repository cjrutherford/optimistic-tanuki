## Follow-up review: receipt retention and startup

Directory receipts remain durable and **unbounded**. Social's signed exact-pair acknowledgement removes the outbox row, but that alone does not fence requests already read by another worker or delayed in transit. Deleting the receipt after an acknowledgement, even after checking that Social no longer has the exact event, would allow such a retry to execute reconciliation again. An arbitrary TTL cannot establish that all requests have ended. Safe bounded cleanup needs an authoritative exact-event absence check and a durable protocol that fences every stale or in-flight apply against cleanup (including crashes and multiple workers); neither is provided by the current protocol. Do not manually purge receipts while delivery can replay. This is an unresolved S3 acceptance gap, not a bounded lifecycle claim.

The directory Compose services are behind the single global `directory` profile; enabling it activates automatic discovery of all eligible towns, with no per-town configuration. Supply the documented distinct secrets, Redis URL and external Directory database URL before activating the profile; do not invent credentials. The migration job now retries boundedly when the external database is not ready, suppresses driver output which might reveal connection details, and Compose retries a failed job up to three times. Migration failures still require operator investigation after the retry budget; profile-off stacks do not start this job. The application waits for successful migration.

The census performs a new pass 15 minutes after completion, rather than continuously; a late insertion behind its cursor is picked up by a later pass. Normal Social writes must record their outbox event atomically. Direct database writes that bypass the outbox rely on the periodic census and can remain stale until a later completed pass; the census is not a substitute for an atomic event during an outage or repeated failures. Existing isolated tests cover late lower event identities and concurrent replay, but do not prove every crash, delayed request, or production workload.
