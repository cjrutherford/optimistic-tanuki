# R6 OT/TS release closeout design

Scope: R6-01 through R6-05, only client-interface, local-hub and the shared UI and evidence they require. Preserve the current checkout and protected Directory/Compose/root TypeScript work. No commit, push, worktree, shared restart or host dependency installation.

Use the existing RR-01 claim IDs to reconcile public landing, metadata and shared-shell language. Keep qualified early-access wording where the local evidence does not establish production operation. Classify every inventoried claim as VERIFY, COMPLETE, REWORD, RETRACT or DEFER with evidence and its practical limits.

Add one reusable information page in profile-ui, with app identity supplied by route data. Both apps expose public /help and /privacy routes, with links from their landing and account/settings surfaces. Help supplies concrete first-session actions to existing routes and explains audience, account controls and recovery. Privacy explains actual account/shared-service scope, rolling inactivity, activity retention, account deletion, shared audit deidentification, downloaded copies/backups/provider limits and the existing support contact. No new settings, backend behavior, fictional counts, guaranteed delivery or legal assurances.

Verify the new shared component with a focused semantic route test, rebuild both apps, then use the existing private real-service/browser fixture in an explicit R6 mode. Exercise anonymous help/privacy, same-app account controls, working navigation and responsive pages; capture the actual rebuilt revision at 390/1280. Prior R4 journeys remain revision-specific evidence rather than being rerun without a cause.

R6-05 assembles a local handoff with evidence hashes, actual screenshots, reproducible demo steps, external X01–X04 blockers and the project owner as the release decision owner. A completed local checklist is not public deployment authorization. Preserve all earlier receipts unchanged.
