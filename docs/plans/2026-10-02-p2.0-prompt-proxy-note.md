# P2.0: routing civic-briefing's model calls through prompt-proxy (D5)

Date: 2026-10-02. This is the research slice for D5. No code was changed.

## What each side does today

**civic-llm** (`libs/civic/llm/src/gateway.ts`):

- It calls Ollama directly. Its native mode (`GATEWAY_API=ollama`, chosen
  automatically for `:11434`) posts to `/api/chat`:
  `{ model, messages, stream: false, think: false, format: <JSON schema or
'json'>, options: { temperature, seed, num_ctx, num_predict,
repeat_penalty, repeat_last_n } }`.
- Native mode exists because Ollama's OpenAI-compatible endpoint silently
  truncates long prompts to about 2k tokens.
- The HTTP call goes through an injectable `fetchImpl`.
- **Provenance is recorded by civic itself** in its own store
  (`llm_generations`: prompt and response hashes, model, timing).
  Append-only triggers guard it.

**prompt-proxy** (`apps/prompt-proxy`):

- It is a TCP microservice with one message pattern,
  `{ cmd: PromptCommands.SEND }`. It posts the payload **unchanged** to
  `${API_BASE_URL}/api/chat` and returns Ollama's raw response.
- There is no validation pipe, so fields outside `GeneratePrompt` (`think`,
  a schema-valued `format`) reach Ollama untouched.
- Its timeout is `PROMPT_PROXY_TIMEOUT_MS`, 120 s by default.
- Errors become `RpcException(message)`, so the HTTP status is lost.
- It logs every response's content and token usage. It stores no
  provenance.

## Answer: yes, with no change to civic-llm

civic-briefing can supply a `fetchImpl` that forwards the native request body
to prompt-proxy over TCP (`ClientProxy.send({ cmd: 'SEND' }, body)`) and
wraps the reply as a `Response`.

- The bytes Ollama sees are identical to a direct call, so prompts,
  structured output, context size and seeds are unchanged.
- civic-llm's parsing, validation and provenance recording run as they do
  now.
- The parity gate is unaffected: replay uses `replaySummarizer` and calls no
  model.

## Gaps, for P2.3

| Gap                                                           | Effect                                                                                                                                            | Proposed handling                                                                                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GeneratePrompt.format` is typed `'json'` and lacks `think`   | Compile-time only; runtime passes through                                                                                                         | Widen the type in `libs/models` (`format?: 'json' \| Record<string, unknown>`, `think?: boolean`), so civic-briefing can use it honestly               |
| 120 s proxy timeout vs civic's per-call timeout (up to 300 s) | Long brief generations fail at the proxy first                                                                                                    | Set `PROMPT_PROXY_TIMEOUT_MS` at or above civic's longest call; the ClientProxy timeout must match                                                     |
| Errors lose their status (`RpcException(message)`)            | civic maps failures to `timeout`, `unavailable` or `invalid` from HTTP status                                                                     | civic's `fetchImpl` maps proxy errors to `unavailable` (with timeout text as `timeout`); optionally, prompt-proxy includes the status in the RPC error |
| The proxy logs full responses                                 | Briefing evidence ends up in logs                                                                                                                 | Acceptable for now. Note it for the operator, or drop that log line to verbose                                                                         |
| One Ollama host behind the proxy (`API_BASE_URL`)             | civic's planner (`qwen3.5:4b-q8_0`) and writer (`gemma4:e4b-it-qat`) must be pulled there and share its GPU with the platform's other model users | Deployment item (P5.2). Record the model list in compose                                                                                               |
| No streaming or abort across TCP                              | A civic-side abort doesn't stop the Ollama call                                                                                                   | Acceptable: civic waits for the timeout, then records the failure                                                                                      |

## Recommendation for P2.3

1. Add `PromptProxyFetch` to civic-briefing as an `@Injectable` taking
   `ClientProxy` (`ServiceTokens.PROMPT_PROXY`). It should be about 40 lines,
   with tests against a fake ClientProxy.
2. Configure civic-llm with `api: 'ollama'` and that `fetchImpl`. Keep the
   direct `LLM_BASE_URL` path behind an environment switch for local
   development without the proxy.
3. Make the small `GeneratePrompt` type widening.
4. Align the timeouts in civic-briefing's config and prompt-proxy's compose
   environment.

Nothing here needs a decision beyond D5, which is already decided.
