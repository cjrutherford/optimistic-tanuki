# DF-007 B3: Permissions metadata and owned-profile identity pages

B3 is locally verified on 2026-10-18. Independent review is GO, all CI-aligned pre-E2E gates passed, and the private Authentication/Profile/Permissions run passed both suites and all 20 tests. **DF-007 and RR-11 remain open.**

Profile now offers an authenticated internal lookup of the account’s profile IDs in bounded keyset pages. It selects only IDs and owners, rechecks ownership and page progression, and rejects malformed input. These are live, unfenced reads: reaching an empty or final page cannot establish a stable inventory or complete zero-data result while concurrent writes remain possible.

Permissions independently validates the same account session, obtains profile IDs only from that lookup, and returns a bounded allowlist of the account’s role assignments. It disables eager relation loading and omits target identifiers and shared role, scope and permission definitions. Page, assignment, time and response budgets stop oversized previews; failed or malformed reads retain explicit partial-coverage markers.

Authentication includes Permissions in its internal coordinator and validates the participant identity, subject, contract version, status and aggregate response budget. The dedicated Authentication integration closure now includes Permissions and its database; the shared stack receives the matching service configuration. No public route, download, deletion, schema or UI is added. Every preview remains incomplete and non-downloadable.
