# DF-007 N02 — OT/TS session and permission caches

N02 is locally verified for Optimistic Tanuki (`client-interface`) and Towne Square (`local-hub`). The [inventory](../evidence/df-007/n02-cache-inventory.json) records seven store and authority boundaries. The [receipt](../evidence/df-007/checkpoint-n02.json) records the frozen sources, checks, runtime provenance and limitations.

Two concrete gaps were repaired. A Gateway replica could reuse a cached grant after another replica changed a role. Authorization now reloads Permissions on each check; memory, file and Redis diagnostic entries cannot authorize requests. Existing generation fences still discard an overlapping stale loader result. Role/permission definition edits clear diagnostic entries without changing existing RPC response contracts. An internal helper validates and invalidates an authoritative set of account-owned profile IDs, preserving unrelated profile entries.

OAuth callback grants previously stored a raw session token in Redis. New grants contain an opaque session-row reference and account/profile/app binding. After the Gateway consumes the origin/nonce-bound one-time grant, Authentication checks the durable row, revocation, signed claims, account access and current Profile ownership before returning the token. Cookie and legacy bearer response formats are preserved. Local and Redis account invalidation remove matched linked states and callback references. Pre-login state has no established account identity and expires; it is not silently attributed to an account.

One private runtime case passed all seven stages with zero skips. Two independent HTTP harness processes exercised the production Gateway guard, cache, mutation wrapper and OAuth redemption methods against real Authentication, Profile, Permissions, PostgreSQL and Redis. It proved immediate replica denial after role revocation and shared-role edits; account-profile invalidation with counterpart preservation; cookie/bearer redemption and logout; wrong-origin/replay/expiry/legacy/revoked denial; profile ownership changed after grant creation; account-scoped OAuth invalidation; and process restart. Independent counts matched across all three databases, Redis had zero keys, temporary tables were zero and private Docker resources were removed.

Authentication used a fresh image. Profile, Permissions and the migration toolchain were pinned to the recorded schema-unchanged images. The external provider handshake was bypassed through the trusted Auth session-reference command. This qualifies the backend seam, not a full production Gateway deployment, browser journey or external-provider flow.

Focused coverage qualifies 131 distinct cases across the initial selected run and corrected subsets. The initial combined Gateway run had two wrapper failures; both passed after repair in the final 71-case subset. The final four store tests include canonical account invalidation. Authentication's seven reference tests passed. Thirty-five local CI contract checks, owning production builds/lints, the scoped OT/TS development build and migration governance passed. No schema changes were made.

A source reviewer questioned current profile ownership at redemption. Inspection showed that the resolver already requires an exact live ownership reply from Profile, in addition to the row and signed-claim checks. The private ownership-transfer case returned denial and settled that concern. The reviewer did not issue a harness GO; runtime acceptance is the parent's executed evidence. Earlier harness failures and cleanup outcomes are retained in the receipt.

Each authorization check now incurs an owning-service RPC and fails closed when that service is unavailable; no capacity or latency SLO is claimed. PKCE and guardian registration context remain bounded protocol secrets. Legacy raw-token callback grants are rejected, so a sign-in in progress during upgrade may need to restart. D00 still owns permanent account-wide fencing, profile discovery and deletion; N06 owns browser cleanup. No public controls or UI were added. Overall export remains incomplete with no artifact; DF-007 and RR-11 remain open.
