# N07 — OT/TS local provider-link contracts

**VERIFIED locally for application-held provider identity and grant boundaries.** See the [receipt](../evidence/df-007/checkpoint-n07.json). No external provider handshake, remote grant revocation or provider account deletion is claimed.

Authentication persists the provider name/subject and optional email/display name in `oauth_provider`. The registered and freshly migrated entity has no upstream access-, refresh- or ID-token column. The Gateway exchanges an upstream token only to fetch a whitelisted identity. A focused projection regression proves token sentinels in both token and user-info responses do not enter the returned identity or an Authentication RPC. N02's callback store keeps local session-row references rather than bearer payloads.

Ordinary unlink previously read the user and provider count outside a transaction. Two concurrent requests could each decide another method remained. It now locks the account's User row, reads/counts/deletes through transaction-bound repositories and verifies the exact local linkage is gone before commit. The original link ID is captured before TypeORM remove clears entity primary keys. Last-method protection, missing-user failure and counterpart scoping remain explicit.

One fresh PostgreSQL fixture used checked-in Authentication migrations and the actual OAuthService. Concurrent unlink of two providers on a passwordless account allowed exactly one removal and left one sign-in method. Another account's linkage remained. An injected SQL-delete trigger forced failure; the transaction rolled back and retry succeeded after the fault was removed. All public-table counts matched the post-migration baseline after cleanup, reconnect readback was clean and the disposable container was removed. Unused sign-in dependencies were inert fixtures; this was not a Gateway/session/provider journey.

Authentication focused tests passed **23**, the Gateway projection suite passed **60**, and owning builds/lints and local pre-E2E/migration checks passed. The earlier fixture lint error in cleanup control flow was corrected; final runtime/lint evidence is separate.

Unlink means removal of the local sign-in identity. It does not revoke provider-side consent, delete the provider account or invalidate unrelated local sessions. Application client credentials are shared operator configuration, not an individual's grant to destroy. Whole-account deletion may remove the final linkage through the later D01 owner operation; ordinary unlink keeps its lockout guard. Shared disconnect controls and their wording remain U01–U03; real external flows and production qualification stay outside this local loop.
