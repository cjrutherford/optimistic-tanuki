## Scope and outcome

RR12-I02 adds an immutable source check to the production deploy checkout, passes the workflow event SHA/run identity into the OT and TS browser-image builds, and adds OCI source/revision labels to CI-built images. Each production Dockerfile writes a manifest over every regular file in its public browser output, including lazy chunks. The manifest excludes server output, private files, environment values, and itself; it rejects symlinks and unsafe paths.

The read-only public probe compares every manifest-listed browser file and every same-origin script, stylesheet, module-preload, and script/style preload URL found in the served root HTML. It keeps off-origin and otherwise unchecked critical references visible without fetching them or retaining URL query strings. A query, fragment, unsupported scheme, missing stylesheet URL, or invalid encoded path cannot silently disappear from the result. A root HTML hash is recorded as a separate SSR response fingerprint and is never compared with a static build `index.html` hash. A matching self-reported manifest revision still does not prove the running image or Argo revision.

The evidence is intentionally limited to literal critical references in the root HTML and files listed by the browser manifest. It does not inventory nested CSS imports, resources created dynamically at runtime, authenticated pages, SSR/server code, or external resource bytes. External critical resources produce an explicitly qualified status. The OT source index currently includes external Highlight.js script and stylesheet resources; they are identified in the result and remain unchecked by this probe.
