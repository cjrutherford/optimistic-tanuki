## Public-write control inventory and deployment

The gateway now separates broad socket-peer traffic buckets from authenticated write buckets. Route overrides cannot shrink the broad peer quota, and a forged `X-Forwarded-For` cannot choose either tracker. Identity limits use the authenticated account, not a client-supplied profile. Owning service access checks remain required; a rate limit does not authorize a request.

| Surface                               | Production default                                                         | Override                                                                                                                      |
| ------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Broad network traffic                 | 100/second, 300/10 seconds, 1,200/minute                                   | `THROTTLE_SHORT_LIMIT`, `THROTTLE_MEDIUM_LIMIT`, `THROTTLE_LONG_LIMIT`                                                        |
| Social post, comment, vote, reaction  | 30, 20, 20, 60 per minute respectively                                     | `THROTTLE_SOCIAL_POST_LIMIT`, `THROTTLE_SOCIAL_COMMENT_LIMIT`, `THROTTLE_SOCIAL_VOTE_LIMIT`, `THROTTLE_SOCIAL_REACTION_LIMIT` |
| Forum topic/thread/post writes        | 20/minute                                                                  | `THROTTLE_FORUM_WRITE_LIMIT`                                                                                                  |
| Classified creation                   | 10/minute                                                                  | `THROTTLE_CLASSIFIED_CREATE_LIMIT`                                                                                            |
| Privacy block/mute; report submission | 20/minute; 10/minute                                                       | `THROTTLE_PRIVACY_WRITE_LIMIT`; `THROTTLE_REPORT_LIMIT`                                                                       |
| Authenticated chat socket writes      | 60/minute per account across connections                                   | `THROTTLE_CHAT_WRITE_LIMIT`; relaxed development/test default 1,000, ceiling 2,000                                            |
| Authentication/email actions          | Existing route limits, including production login 10/minute                | Existing authentication configuration; dev login/session allowances do not establish production abuse proof                   |
| Uploads                               | Existing body-size, encrypted storage, scanner and A01/A02 audience checks | Owning asset configuration; large-media reliability remains RR10-I01                                                          |

Defaults apply with no profile override. `THROTTLER_PROFILE=relaxed` requires explicit `NODE_ENV=development` or `test`; other environments reject it at startup. Override values must be positive integers within source-defined ceilings. Production composition must forward only desired bounded overrides. The limiter is in-memory per gateway process: restart clears counters and multiple replicas do not share quota. This is an initial safeguard, not distributed denial-of-service protection. Deployments behind one proxy can share the broad socket-peer bucket and must size it deliberately.
