# DF-007 B6 — Bounded Forum authored-content preview

**Status: locally verified internal preview; DF-007 remains a mandatory release prerequisite and RR-11 remains unaccepted.** B6 adds Forum as the fifth sequential participant. Its output remains partial and unfenced.

## Result and boundary

Forum returns a bounded partial snapshot of authored Topic, Thread, and ForumPost rows. Authentication validates the requested subject and requires Auth's returned `data.userId` to match before Forum resolves identity or reads its repositories. Trusted profile IDs come from Profile in pages of 100, capped at 1,000 IDs and ten pages. Forum queries rows matching both account ID and trusted profile IDs, selects explicit scalar fields, disables eager relation loading, uses ordered UUID keysets, and rechecks returned rows. Each collection is capped at 1,000 returned scan candidates plus one truncation probe. These caps do not bound internal database work or prove SQL cancellation.

Auth and Profile calls have first-response timeouts of at most three seconds, each capped by remaining participant time. The 15-second Forum participant budget starts before Auth validation and covers Auth/Profile RPC latency and Forum reads. Authentication gives Forum a 16-second coordinator response window. This is not an account-wide deadline.

Authored sanitized HTML remains an inert JSON string and may contain author-supplied URLs. The preview does not parse, render, fetch, dereference, or traverse it. Separate ForumLink rows, media bytes/provider paths, reports, moderation history, operational fields, foreign parent text, and foreign replies are omitted. A target-authored post in a foreign-authored thread may include its `threadId` as an opaque reference. Embedded media/link references and legacy authorship provenance remain unresolved. Empty or failed reads do not establish completeness.
