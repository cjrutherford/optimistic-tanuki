## Behavior

The established Assets snapshot registry and Auth pull client now live in the shared Storage library with thin participant wrappers. Videos and Assets share exact lease scope, parent binding, bounded reads, verified terminal counts/digest, stale-scope release and cleanup behavior. The registry retains the actual owner promise through cancellation/shutdown and keeps failed cleanup charged against capacity. Assets protocol strings and public wrapper APIs are preserved.

The Authentication coordinator records Videos only after its capture verifies. It closes Videos, then Assets, then Profile before acknowledging progress. Capture/cleanup failures remove the affected progress markers; lost leases cannot acknowledge completion. The new marker represents a database capture, not verified portability of every referenced media object or a durable artifact checkpoint.

Review found that the cooperative capture timer did not bound waiting for a database connection. Videos now configures a three-second connection/pool wait timeout. A fresh PostgreSQL fixture with an occupied single-connection pool verifies failure and cleanup within that bound. The 45-second capture budget remains cooperative; it is not a hard process/network cancellation guarantee.

The checked-in Videos runtime image also installed an unused watcher and recursively changed ownership of its full dependency tree. The initial build stalled in that ownership step and was stopped. The image now installs its production dependencies, runs the Node entrypoint, and makes only its storage directory writable by the service user.
