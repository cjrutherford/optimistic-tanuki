## Findings and repairs

Review found that profile images can be stored as inline data URLs. The first implementation copied those fields while describing them as references only. The final preview excludes both image columns from the database selection and returned profiles, reports that omission explicitly, and keeps image/video portability uncovered. No images were removed from stored profiles.

The preview now limits strings to 4,096 characters, each participant response to 512 KiB, and the combined response to 1 MiB. Over-budget data is omitted with explicit partial-coverage markers. These limits bound returned payloads. They **do not bound database read memory**: selected text is materialized before the checks, and Profile loads up to 1,001 rows to detect its 1,000-row limit. Full export still requires bounded retrieval, pagination or streaming, and readback.

The first TCP run passed 17 tests and failed three denial assertions because Nest returns structured errors and the tests used `String(error)`. The repaired assertions inspect the actual message and serialized error for credential/SQL leakage. The final run passed both suites and all 20 tests, including the inline-image fixture, multi-scope ownership, foreign-account exclusion, missing/invalid credentials and scope, and revocation after logout.

The documented dedicated E2E stack now includes Profile and reuses the existing CI database-setup image recipe. The service manifest, CI job, and local runner supply the required service closure and explicit fixture-cleanup configuration.
