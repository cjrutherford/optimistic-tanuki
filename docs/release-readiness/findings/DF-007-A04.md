# A04 — artifact jobs and recovery

**VERIFIED LOCAL OT/TS, 2026-10-24.** OT/TS only. The twelve-service export/download journey is qualified by [A07](DF-007-A07.md). Completed scoped jobs now publish a relative download URL after verified storage and owner cleanup.

Authentication stages a private artifact only after all twelve owner captures pass coverage checks. It persists a descriptor under the current database attempt/lease nonce before writing encrypted bytes. Owner cleanup finishes before the job acknowledges the staged artifact. Preparation, owner-cleanup or finish failures compensate only that attempt's artifact; failed compensation retains its durable descriptor for retry. Public status strips private descriptors and session references.

Create/resume returns running status while work proceeds in the background. Two launches per process are reserved before asynchronous claiming. Restart recovery resolves an opaque existing session-row UUID, reauthorizes it, and never persists the bearer credential in the job. The Auth bootstrap now uses one hybrid HTTP/TCP provider graph so startup recovery is registered once.

Cleanup does not require a live user session. Missing/revoked-session recovery claims ledger authority, removes staged bytes and fails the export. A storage fault keeps cleanup-pending custody; a later scan retries without looking up a user token. This closes the first source review's orphan finding; the follow-up source review reported GO.

A fresh private PostgreSQL database ran all thirteen registered Authentication migrations, then four artifact-ledger cases and five cancellation/lease cases. The ledger cases use twelve synthetic verified owner streams to isolate real database/filesystem behavior: intent ordering, new-worker recovery/retry, stale nonce rejection, quota, revoked-session cleanup and injected cleanup failure. They do not substitute for A07's real owner transport journey. Independent readback found zero job rows, and teardown left zero private containers.
