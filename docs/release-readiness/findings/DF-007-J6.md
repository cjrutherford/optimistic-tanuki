## Behavior

Profile exposes internal open, bounded read, identity-page and release commands. Capture is bound to account, app, job, attempt and lease nonce. Authentication validates the fresh session and the exact running job using PostgreSQL's clock. Profile repeats that check during capture and before and after data-bearing reads. Descriptors omit credentials and nonces. The registry stores scope metadata and an unlinked spool descriptor, not session tokens.

The eleven sources and identity pages come from one Profile capture. Identity pages read indexed bytes from that capture rather than querying current rows. Reads are limited to 64 KiB and identity pages to 100 IDs. The registry allows two outstanding or opening captures, reserves 256 MiB per open within a 512 MiB aggregate budget, and expires handles after two minutes. Cleanup failures retire the handle while retaining its capacity charge. Exact-scope release remains available after session or lease revocation because it returns no account data.

The shared puller checks descriptor scope, file size and SHA-256, canonical base64, strict UTF-8, bounded JSONL lines, stream termination, source counts and dispositions through the actual owner verifier/spool. PostgreSQL timestamp text retains its precision. A staged handle is returned only after the entire file verifies. The job renews its lease during transfer and closes local and remote resources before acknowledging progress. Stable failure codes replace underlying database, session and transport details.
