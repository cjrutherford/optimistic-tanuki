# DF-007 N03 — OT/TS search and secondary stores

N03 is locally verified for Optimistic Tanuki (`client-interface`) and Towne Square (`local-hub`). The [inventory](../evidence/df-007/n03-search-store-inventory.json) names the primary search/history stores, computed discovery results, native indexes and excluded boundaries. The [receipt](../evidence/df-007/checkpoint-n03.json) records the exact source, catalog and cleanup evidence.

The traced searches use primary owner repositories and Profile RPC. A bounded scan of 756 tracked source files found no external search-engine, materialized-view, full-text-vector or foreign-table implementation in the reviewed paths. The fresh catalog check covered eleven databases: 74 ORM tables including junctions, eleven migration stores and two migration-only Profile tables, for 87 physical tables, 781 columns and 161 B-tree indexes. Every index was attributed to its source table. No views/materialized views, generated/full-text columns, foreign tables, custom mirror triggers or unregistered application schemas were found. This is local source/schema evidence, not a claim about uninspected deployed services.

The Profile catalog also contains `goal`, `project`, and `timeline.relatedGoalId/relatedProjectId`, all defined by the initial migration but absent from current ORM registration. They are explicitly reconciled as legacy primary structures. Their presence does not approve ownership, capture or deletion of their contents. Primary counters and channel playback state likewise remain owner-table fields under their existing dispositions and later deletion adapters; they are not silently classified as independent search mirrors.

Search history is durable personal data. Social's existing search method writes it after a profile-bound request, including a request through the Gateway GET route. The new internal cleanup helper validates a proven owned-profile set and removes only matching history, including equivalent UUID letter case. Process-local generations and write draining suppress older requests and overlapping cleanup windows. A failed SQL delete rejects and can retry. New independent searches after acknowledgement may record again; D00 still owns distributed/permanent fencing and the authenticated account-deletion workflow.

The same service's community discovery queries lacked a privacy predicate. Search and suggestions now require `isPrivate=false`; post visibility handling is unchanged. The real database case confirmed public results while excluding the private community.

One private runtime case passed with zero skips after an explicit migration exit-zero barrier. It proved cleanup across two owned OT/TS profiles, preservation of a counterpart and an owned excluded-scope profile, legacy UUID handling, independent forced-index reads, a late-query race, a blocked real SQL insert, SQL deletion failure/retry, and restart readback. Independent counts and schema shape matched across all eleven databases; temporary tables and private Docker resources were zero. The source service used real Social/Profile repositories with synthetic configuration and controlled scheduler/SQL faults. This was not an Auth/Gateway/browser journey.

Twelve focused Social tests, 35 local CI contract checks, the owning production build/lints, the scoped OT/TS development build and migration governance passed. A flat Luna source review found no P1/P2 defect. The private N01–N03 probes are now opt-in, so ordinary selection does not require their local ports. A separate registration-only probe intentionally skipped exactly three cases; it is not counted as runtime coverage. N01/N02 callback bodies retain the same syntax trees. Earlier harness failures, including an invalid pre-migration baseline, remain recorded in the receipt.

N03 does not qualify browser cache/account-switch behavior, search UX accuracy, statistical recomputation/retention, deployed external sinks, backups or physical byte erasure. Full account export, artifacts and deletion remain incomplete; DF-007 and RR-11 remain open. No UI or public deletion endpoint was added.
