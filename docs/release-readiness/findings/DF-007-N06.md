# N06 — OT/TS browser account boundaries

**VERIFIED locally in system Chrome against both rebuilt applications.** See the [receipt](../evidence/df-007/checkpoint-n06.json). The HTTP session/profile responses are explicitly scripted to control races; this is browser-state evidence, not another real Authentication or external OAuth qualification.

A rejected current-session response also clears shared caches and other tabs; the final browser cases exercise a scripted 401 before signing in again. This covers the client response to session loss, without claiming a backend deletion endpoint.

Both applications now reuse a shared generation guard. An old restore cannot overwrite a newer account or repopulate state after logout. Logout clears local state before its network call, including when that call fails. OT profile persistence rejects a mismatched current account. Explicit owned legacy auth/profile caches are removed; themes, custom palettes and device preferences are preserved.

App-scoped BroadcastChannel notifications contain only an invalidation marker. An account change/logout clears other open tabs' old state without issuing logout requests with another tab's newer credential. Shared search requests and notification loads are cancelled or generation-fenced; cached results, unread state and decoded legacy Forum identity clear at the session boundary. Old observable references cannot replay the previous account. New-generation callers explicitly request new data; this change does not promise automatic suggestion refresh for an old subscription.

Presence no longer derives the actor from a generic localStorage `user` object or confuses profile and account IDs. It submits the status and lets the authenticated Gateway bind the account. The obsolete identity cache is removed on OT logout. Cookie email-action routes do not write new bearer caches; the transitive source inventory records legacy token paths and the keys retired by cleanup.

The final private Nx E2E run passed **six cases**: OT and TS at desktop, mobile and tablet Chrome viewports. Each used the actual Angular app to hold account A's response, sign in account B, release A, confirm B remains current, open a second tab, and sign out despite a simulated 503. Both tabs cleared, owned/retired bearer caches disappeared and device preferences remained. Browser diagnostic sentinels were absent. Per-viewport screenshots and reports are recorded. This is not physical-device/Safari qualification.

Focused units passed: OT auth/presence 37, TS auth 12, shared session helpers 3, search cache 16, notification cache 18 and Forum identity reset 1. The earlier no-tests Forum selection is not counted as coverage; a focused regression was added. Final builds/lints and local pre-E2E/migration checks passed. Only private SSR processes were stopped; shared Docker infrastructure was untouched.

The same-source browser logging boundary suppresses unreviewed console payloads while retaining fixed event/severity metadata. Browser-managed network panels, extensions and operator telemetry are not application persistence and are not erased by this helper. A failed logout HTTP request does not prove server-side credential revocation; N02 supplies the real successful cookie/bearer revocation evidence. Public account-deletion controls and durable global deletion remain U01–U03/D00. The legacy notification socket transport is not newly qualified by these state-reset tests; live user journeys remain R4 work.
