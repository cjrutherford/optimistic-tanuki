# DF-007 J12 — HLS media portability

**Status: locally verified bounded owner/media component.** This extends the existing Assets capture with finite HLS playlists and MPEG-TS segments. Account artifacts, authorized downloads, remaining owners, deletion and shared controls remain open. DF-007 and RR-11 remain open.

The shared Storage helper parses a bounded local playlist subset produced by the video pipeline. It rejects external URLs, keys, master playlists, arbitrary directives, malformed URI/duration pairs and invalid UTF-8. HLS bytes stay buffered until the parser and account-owned reference callback both pass. Assets checks all referenced IDs in batches against the same read-only transaction and captured Profile scope. Missing, foreign, inactive and non-video rows fail capture. All owned objects still pass through authenticated encrypted-storage reads; the relationship query is not a media-integrity check.

Captured manifests retain their original bytes, SHA and API references, with an explicit list of referenced Assets. The shared rewrite helper resolves those references through the verified media manifest index, requiring safe local MPEG-TS file names. Derived playlists need their own hash when a durable artifact is assembled. This component does not create an account download.

Assets also now bounds database connection/pool waits to three seconds and logs only allowlisted host, port and database diagnostics. Raw configuration and credentials are no longer logged. The capture deadline remains cooperative.
