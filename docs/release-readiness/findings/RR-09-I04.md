# RR09-I04 — OT feed: edit own post

**Status:** PLANNED — user-reported, not yet reproduced or accepted. RR-09 remains GAP FOUND. This bounded repair follows RR09-I03 and precedes RR09-V01 and RR-10.

## Trigger and source evidence

The user reported that a signed-in user cannot edit their own posts directly from the feed and asked whether it was already scheduled or fixed. The report is unverified at runtime.

The current source exposes an `Edit post` menu item only when `PostComponent.canEdit()` matches the selected `currentUserId` with the post's `profileId` (`libs/social-ui/src/lib/social-ui/post/post.component.html` and `post.component.ts`). `startEdit()` fills the title/content editor, `saveEdit()` emits `postUpdated`, the feed binds that event to `updatePost(post.id, $event)`, and `FeedComponent.updatePost()` sends the update and replaces the matching feed row. A unit test checks the `canEdit()` predicate and the feed suite checks model update behavior. These source/unit paths are not live proof that a selected owner can edit from the feed, save successfully, or see the change after reload.

## Bounded implementation and acceptance

Begin with authenticated OT reproduction through the feed UI. Use a synthetic retained account and a precisely identified own-post fixture created through normal application APIs/UI; do not mutate an unrelated existing post. Record the exact fixture IDs and restore them through the ordinary owner-facing delete path with exact-ID readback. No SQL mutation or broad reset is in scope.

The repair slice owns only a confirmed gap in this selected-profile feed-edit path. Its live cases must cover:

1. With the authoring profile selected, the own-post menu offers Edit; the editor is reachable by keyboard and contains the exact saved title/content.
2. Cancel leaves the row unchanged. Save updates the title/content, the feed row updates without a duplicate, and reload preserves the values.
3. A non-owner cannot see or invoke Edit. If the same user has multiple owned profiles, edit availability follows the selected profile: the matching profile can edit its post and another owned profile cannot.
4. A failed save leaves a recoverable error/state, preserves the original persisted row, and allows retry without duplicate posts.
5. Exact fixture cleanup and readback pass after the run; no unrelated post is changed.

Required gates are focused social/post and client-interface unit tests, affected lints, the full development build and authorized app-container refresh, focused system-Chrome authenticated live cases, exact cleanup/readback, and independent review. Preserve RR09-I03's authenticated-control assertions as regressions. V01 must explicitly repeat own-post editing as part of its final feed acceptance.

This scheduled checkpoint is not evidence that the reported issue is a product defect, nor that editing is already fixed. If the reproduction shows all acceptance cases already work, record the evidence and close the checkpoint as verified without a source change. If it confirms a gap, repair it here before V01.
