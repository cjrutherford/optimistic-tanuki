## Changes

The reusable Storage sink checks expected account/participant identity, ordered source exhaustion, counts, checksums and the producer's terminal return. It applies per-capture byte/deadline limits and awaits each file write. It opens a private file, immediately unlinks it and removes its temporary directory, then holds only its descriptor. Completed handles expose bounded reads and immutable metadata. Failed, cancelled, concurrent or incomplete producers yield no handle. Cleanup closes active readers and the descriptor; process exit releases the unlinked file. Accepted terminal evidence and expected options are copied so producer mutation cannot change their meaning.

The coordinator renews only its current running attempt, lease nonce and unexpired DB-clock lease before capture and at each chunk. A stale attempt stops without acknowledging completion. It records only `capturedDatabaseOwners: ['authentication']` after staging verifies, and closes staging before finishing the still-incomplete job. Errors use bounded codes, with no tokens, participant content, paths or file metadata in the ledger/status. The Authentication history reader validates the new progress field against unique known owner IDs; [updated field dispositions](../evidence/df-007/authentication-owner-fields-j3.json) preserve the earlier J2 manifest separately.

These are temporary verified owner bytes for orchestration. They do not persist as a downloadable account artifact or survive as an operation checkpoint across an app restart. Explicit retry recaptures data. Complete per-owner/non-ORM coverage, portable files and the artifact lifecycle remain required.
