**Proposed implementation:** extend the existing shared common-ui public-information/contact primitives for the remaining approved static pages; do not create a new library unless a concrete reuse need emerges. Shared UI must not synthesize legal language or default to permissive copy. Reuse current design tokens/common UI primitives and retain each product's approved identity.

**Routes and visibility:** explicit public routes for only approved content (expected policy/community-use and privacy destinations) in both route tables. Contact is already implemented. Do not add a public status destination this release. If a process is unavailable, do not render a form or mailto link that implies it works. No account deletion/export action is added by I03 unless I02 and DF-007 establish a separately bounded, supported flow.

**Disclosure content:** privacy page should describe the gateway-declared session-cookie behavior, OT's serialized profile-list/selected-profile local-storage use, TS auth-state's cookie restore (while limiting claims to that reviewed file), observed third-party resources by product, and the RUM payload fields and path normalization. Do not claim an exhaustive inventory, no tracking, or noncollection on authenticated routes until verified. **Verification for a later implementation slice:** direct-load and refresh each approved route while signed out and signed in; confirm the fallback route does not swallow policy paths; verify all links land on approved, reachable destinations; test keyboard navigation, headings, focus, mobile reflow, and accessibility; compare displayed text against the signed-off decision record; ensure OT and TS show their own accurate product disclosures; confirm no new external resources or telemetry fields are introduced; and verify production bundle identity in RR-01/RR-12.
