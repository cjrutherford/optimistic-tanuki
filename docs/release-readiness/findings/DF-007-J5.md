# DF-007 J5 — Legacy Profile data and references

**Status: locally verified database reader integration.** Profile capture now includes the retained goal/project tables and Timeline legacy links discovered in J4. The unsupported-data guard is replaced by owning-data adapters. Five migration-owned tables now contribute to one read-only repeatable-read capture, with eleven ordered stream sources. This is not a remotely accessible snapshot or an account artifact; item 1, DF-007 and RR-11 remain open.

## Behavior

The legacy reader uses the existing capture transaction and bounded query callback. UUID keyset paging includes the minimum UUID and has no preview row cap. SQL-bounded prefixes and length metadata precede full Unicode text chunks; exact code-point and UTF-8 byte totals are checked. Stored integers, nulls and SQL timestamp microseconds are preserved. Parent abort/deadline errors propagate without becoming generic read failures.

Ownership remains each row's userId. Profile, Timeline, Goal and Project references expose an ID only when the target belongs to the exporting account. Foreign references receive an explicit redaction, and null references remain null. Circular Goal/Project references are projected without graph traversal. Timeline's two legacy links receive the same checks. Foreign rows are neither exported nor modified. The [field dispositions](../evidence/df-007/profile-owner-fields-j5.json) document all five tables and their references.

## Verification

The final enabled PostgreSQL selection passed **three suites and eleven cases, with zero skips**, using actual Profile migrations in a fresh isolated database with synchronization disabled. A legacy fixture exercised 1,006 goals and 1,006 projects, minimum UUIDs, complete Unicode text, timestamp precision, nulls, stored negative integers, circular references and foreign-ID redaction. Source fingerprints before/after matched. The integrated owner case also staged long Goal/Project text through the actual verifier/spool and preserved a foreign row. Existing snapshot, media, guardian privacy, cancellation and cleanup cases passed with the expanded source list. Six focused legacy-reader unit tests passed separately. Profile production build, lint and scoped format checks passed. No schema migration was added.

Independent readback found zero fixture rows in all five tables. The private PostgreSQL container and its anonymous volume were removed. The first PG selection had ten passing cases and one fixture assertion failure: project text intended for chunking was below the threshold. The fixture was enlarged; the narrow repair passed, then the complete eleven-case selection passed. The [receipt](../evidence/df-007/checkpoint-j5.json) keeps these runs separate.

Authentication is stubbed in the owning-reader tests; only the unrelated Storage adapters' UUID dependency is substituted. The reader, emitter, spool and database are real. The six-test unit result is retained in the Luna tool-output handoff, without a raw log file. No live Auth/RPC, application-container, browser, CI-run, restart or production qualification is claimed. J4's earlier proof and field manifest remain unchanged.
