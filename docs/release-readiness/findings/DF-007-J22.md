# DF-007-J22 — Post/Link associations and safe references

**Status:** locally verified at the private PostgreSQL scope; DF-007 and RR-11 remain open.

Post now owns the explicit `post_link` junction. Internal link creation requires `{ dto, actor }`, validates the post ID, account/profile actor and HTTP(S) URL, verifies the matching owned Post and saves the association transactionally. Shared links are immutable through update/remove. Post input cannot mass-assign link relations, and visible list reads load links instead of replacing them with an empty array. No checked-in public Gateway Link caller needed adaptation.

The partial Social preview reads associations only through proven-owned Post IDs, in batches of 100 with a 1,000-row bound. It validates IDs, membership, scope, duplicates and URLs. Normal link URLs are allowlisted; recognized asset URLs become opaque IDs with `referenceOnly: true`. Standalone Links, foreign Post content and attachment storage paths are excluded. A recorded association is not proof of historical authorship, consent or asset ownership. No historical rows were backfilled.
