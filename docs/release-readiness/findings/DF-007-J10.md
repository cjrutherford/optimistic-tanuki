# DF-007 J10 — Videos database ownership

**Status: locally verified database component.** The Videos reader captures seven retained tables using all identities from a leased Profile snapshot. This checkpoint does not register Videos with Authentication jobs or provide a downloadable artifact. Item 1, DF-007 and RR-11 remain open.

## Captured data

Channels require the account user ID and a captured Profile ID to agree. Videos, feeds and program blocks follow owned channels with community checks. Subscription and view history follows the account as actor, including personal views of other creators’ videos. Anonymous and counterpart activity is excluded. Live sessions include account-created sessions and sessions attached to owned channels; other hosts’ creator identities are omitted. Partial actor identity matches fail capture. The [field dispositions](../evidence/df-007/videos-owner-fields-j10.json) record supported fields and exclusions.

Each source uses selected columns, bounded text projections with explicit oversize rejection, and UUID keyset pages. Full supported descriptions are preserved. IP addresses, stream URLs and raw processing errors are omitted. Metadata retains typed media references; it does not establish ownership or byte integrity of those referenced objects. Pending or processing videos fail capture because their output references can change. Ready/failed metadata is a database snapshot, not a lock on processing or media storage.

The component uses one read-only repeatable-read transaction and a private temporary identity table. It creates the table before the read-only transaction, streams Profile pages into it, and never accumulates an account-wide ID array. Leases fence capture, delivered chunks and completion. Capture has a 45-second deadline, SQL statements a 10-second timeout and locks a 2-second timeout. Commit, temporary-table removal and connection release precede terminal proof. Cleanup failure quarantines the reader and error-releases the installed TypeORM PostgreSQL connection; that private driver seam needs review on upgrades.

The existing Assets identity reader now has compatibility exports to a generic implementation in the shared Storage library. Videos reuses it rather than importing another application.

## Verification

Nineteen identity-reader regression tests and five Videos unit tests passed. Storage lint and Assets/Videos build/lint checks passed; the consuming application builds compile the shared code. The private PostgreSQL selection passed **five cases with zero skips**, using three actual migrations with synchronization disabled. Authentication lease and Profile page RPCs were simulated; the database, reader, emitter and spool were real.

The fixture captured 1,006 identities, 1,006 owned channels and 1,006 owned videos, all seven sources, minimum UUIDs and complete supported long descriptions. It checked personal activity on foreign videos, counterpart privacy, late inserts against the existing snapshot and an empty account. Processing races, contradictory ownership/community, oversized text, abort, lease denial and dirty-connection cleanup failed closed. Table fingerprints matched before/after. Independent readback found zero fixture rows in all seven tables and no temporary relations; spool descriptors/directories were empty and the private database container was removed. See the [receipt](../evidence/df-007/checkpoint-j10.json).

The initial fixture attempts failed at a test-only metadata property and then a PostgreSQL seed parameter cast. Both are retained separately; the accepted five-case result is attempt 3.
