# R4-03 — Buyer and seller journeys

Status: **VERIFIED LOCAL / COMPLETE-local**, 2026-10-27.
Scope: OT `client-interface`, TS `local-hub` and required shared services.

The TS buyer submits an offer through the actual listing UI and the seller
accepts through the native confirmation and offer dialog. The UI accurately says
that the card record is pending/unprocessed. Manual card confirmation through the
offline endpoint is rejected; only the declared offline methods are supported.
The unused payment-details action was removed rather than presenting a dead link.

The separate cash receipt path exercises local confirmation/release, canonical
seller and amount selection, private counterpart denial, wallet readback and
idempotent release. Payments now preserves serialized downstream 403/404 and
local state errors across RPC, rather than converting authorization denial to HTTP 500.
Offer creation, acceptance and countering reject unsafe amounts before persistence;
direct payments reject negative seller proceeds and decimal overflow. The runtime
case requires invalid offers to return 400 without creating rows.
These are local financial records, not evidence of card charges, cash delivery,
provider settlement or payouts. No OT Classifieds UI consumer is invented.
