# DF-007 J4 — Current Profile data, identities and inline media

**Status: locally verified reader component, with a legacy-data blocker.** A separate Profile reader captures the three current entity tables in one read-only repeatable-read snapshot. It supplies ordered owned-profile identities, complete retained text, inline PNG/JPEG bytes and role-specific guardian activity. It is registered in Profile's module but has no RPC handler or coordinator integration yet. Item 1, DF-007 and RR-11 remain open.

## Behavior and inventory finding

UUID keyset paging starts without a lower bound and has no preview row cap. Database reads return bounded text prefixes and length metadata; larger Profile and Timeline fields travel as ordered chunks, preserving Unicode code points. Timestamp text retains PostgreSQL microseconds and does not acquire a host-inferred timezone. The reusable Storage emitter packs pages by both serialized bytes and record count, checks ordering, awaits consumers and emits counts/checksum only after every source is exhausted. The reader commits and releases its transaction before terminal proof.

Inline PNG/JPEG data URLs require canonical base64, matching signatures and bounded decoded size. Captured bytes carry exact counts and SHA-256. This checks encoding/signatures, not full image-codec validity. Asset, remote and opaque strings remain exact references, including long references; they are never fetched. This does not capture Assets or Videos content. Guardian rows verify the dependent's Profile ownership. Counterpart user IDs are omitted; guardian-role output also omits profile IDs and changed-field details. Foreign Timeline profile references are explicitly redacted. See the [field dispositions](../evidence/df-007/profile-owner-fields-j4.json).

Migration review found retained **goal/project tables and Timeline legacy links absent from the current entity catalog**. Their adapters are still missing. A bounded same-snapshot guard rejects accounts with owned legacy rows or legacy links on owned timelines; foreign legacy rows alone do not block. This prevents a false complete result while the ownership inventory and legacy adapters are corrected. The existing unfenced profile-ID paging route is unchanged and is not a substitute for remote access to the new snapshot.

## Verification

The final enabled PostgreSQL run passed **two suites and ten cases, with zero skips**, against a fresh isolated database using the actual Profile migration list and no schema synchronization. It checked 1,006 owned Profiles, 1,005 Timelines, the minimum stored UUID, same-snapshot identity equality despite a concurrent insert, exact Unicode reconstruction, microsecond timestamps, PNG/JPEG byte/hash round trips, long/short references, foreign-ID redaction and both guardian roles. It also exercised legacy-data rejection, malformed/oversized fields, cancellation, a deadline reached inside a waiting callback, and actual reader-to-spool success/failure. An injected failure after a staged write left no matching descriptors or paths. Independent readback found zero fixture rows in all five tables; the private container and its anonymous volume were removed.

Focused checks also passed: three authorization-boundary cases, eight legacy-guard cases and five emitter cases across separate narrow selections. Profile production build and Profile/Storage lint passed. No schema change was made. The [receipt](../evidence/df-007/checkpoint-j4.json) distinguishes commands, diagnostics, final passes and evidence limits.

Authentication responses are stubbed in the Profile tests. Only the unused Storage adapters' transitive UUID dependency is substituted; the reader, emitter, spool and PostgreSQL are real. The authorization unit result is retained as the Luna tool-output handoff; it has no saved raw log. This is not live Auth/RPC, application-container, browser or CI-run acceptance. Prior diagnostic failures exposed PostgreSQL substring overload ambiguity, a UUID/varchar join and inconsistent long-reference naming; all were fixed before the final ten-case pass.
