# RR-09-I02 — Shared Appearance focus indicator

**Status:** ACCEPTED — bounded shared-control repair. RR-09 remains GAP FOUND; RR09-I03 and RR09-V01 are still required before RR-10.

**Scope:** Make the keyboard-focused Appearance theme switch visibly identifiable in the dynamically created shared overlay. Preserve its native checkbox, Space activation, modeless panel semantics, and existing Escape focus restoration. This checkpoint does not claim whole-app accessibility conformance.

## Finding and repair

The native theme checkbox is intentionally 0×0 and transparent, while the visible switch is a 48×44 label containing the slider. The old focus rule drew only a low-alpha shadow on that slider. The confirmed pre-fix FOW browser case reached the checkbox by keyboard and observed `outlineStyle: none` on the visible slider. Earlier OT/TS attempts stopped at an unjustified test assumption about initial focus on the panel's Close button; those attempts are harness failures and are not product findings.

`libs/theme-ui/src/lib/theme-ui/theme.component.scss` now gives the visible slider a 3px `var(--foreground)` outline with a 3px offset under `input:focus-visible`. The focus cue belongs to the overlay stylesheet that styles the separately instantiated panel. The checkbox and panel behavior were left intact. A focused component test protects the native checkbox-to-visible-slider relationship; rendered focus visibility is established by live browser evidence below.
