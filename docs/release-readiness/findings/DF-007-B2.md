# DF-007 B2: linked guardian and own security metadata

B2 is locally verified. Independent static review is GO, CI-aligned pre-E2E checks passed, and the private Authentication/Profile run passed both suites and all 20 tests. **DF-007 and RR-11 remain open.**

The internal Authentication snapshot now projects linked guardian permission records relative to the authenticated account. A dependent sees their own recorded DOB; a guardian receives no dependent DOB or account identifiers. Both views omit counterpart contact details, token hashes, full attestation text and transport/lifecycle fields. Own policy-notice records explain that `acceptedAt` means provider acceptance, without claiming inbox delivery. Own email-action metadata includes purpose, app and creation/consumption times, with credential and active-token details omitted.

Profile exports account-relative guardian activity only after checking that its referenced profile belongs to the recorded dependent. The dependent sees their own profile ID and changed field names. The guardian projection omits those fields and the dependent’s identifiers. Self-linked, foreign, orphaned, owner-mismatched or unsupported-operation rows are omitted with partial-coverage markers.

## Findings and repairs

Independent review found that the activity operation column accepts arbitrary text while the exporter trusted its TypeScript union. The final code accepts only `profile.view` and `profile.manage`. An owner-matched `profile.delete` regression failed before the fix and passes with the row omitted and coverage marked partial.

The first root CI run also caught two invalid test fixtures: the truncation and byte-budget cases did not supply the profile-owner rows required by the new ownership check. The tests now reset mock state and return explicit matching owner rows. Ownership enforcement was preserved. Formatting issues were corrected before final source capture; initial failed checks and superseded image iterations remain private evidence.

The always-on notice worker processes pending or leased sending records. Integration fixtures therefore use revoked permissions and a terminal accepted notice. SMTP configuration was explicitly empty; retained Authentication logs contained zero Console/EmailService send or failure patterns. This tests export behavior using synthetic records, not actual guardian activation or email delivery.
