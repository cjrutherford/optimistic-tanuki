# D04 — Videos deletion, processing fences and counterpart history

Status: verified local OT/TS owner adapter, 2026-10-25. Scope: `client-interface`, `local-hub`, and their required shared Videos owner. The qualification exercises existing service paths and synthetic Local Hub data; it adds no frontend video producer.

The owner accepts a signed Videos/action grant, resolves its frozen account/current-profile scope through Authentication, and rejects conflicting account/profile attribution. It inventories all seven registered source tables and bounds every family it changes. Processing holds a separate shared profile drain lease through source access, transcoding, Assets import and staging cleanup. The deletion owner drains processing before installing permanent producer fences. Database triggers collect OLD and NEW direct identities, channel ownership and referenced video/schedule/live ownership, including links from counterpart feeds.

The initial physical test exposed a fail-open array-index mismatch: PostgreSQL TG_ARGV arrays begin at zero, while ordinary ARRAY literals begin at one. The Videos guard now supplies explicit zero-based arguments to the existing identity collector. The final fresh-database test proves direct and parent/reference-derived writes are denied. The generated migration retains its CLI timestamp and reviewed fence-table SQL; an unrelated proposed FK rename was excluded. Frozen SQL matches its source helper exactly.

Worker output is fenced with a separate signed, expiring per-video capability. A durable hashed tombstone and cross-process OS lock prevent later processing from recreating the output. ffmpeg and ffprobe inherit the lock descriptor, so a worker crash does not release custody while its child still writes. The worker validates exact UUID directory custody, rejects unsafe links and over-bound trees, persists its fence before removal, and independently checks absence. The owner retains attribution if output cleanup fails and revalidates authority before acknowledging progress.

Temporary imports now use private per-video directories. Deletion removes only the selected video directories after processing drains. Older randomly named imports without a proven owner block verification; they are not silently removed or treated as absent. Assets owns imported source/derivative bytes and envelope custody under D03; D04 separately removes worker output, attributable import copies and Videos metadata.

Erasure removes the account's views, subscriptions and started live sessions. It removes owned schedules and feeds, clears inbound references to removed video/schedule/live records, and preserves counterpart-authored fields. A video with a counterpart view keeps only an inert private placeholder with its title, description and media references cleared. A channel needed by counterpart views/subscriptions keeps an inert deleted-account placeholder with account/profile storage sentinels and private fields cleared. These placeholders preserve foreign FK/history integrity without retaining the deleting account's identity or authored content.
