## Implemented behavior

The shared post-read policy now intersects audience with current approved account membership for private communities. This also constrains the author-own branch: leaving or losing membership removes access to the author's community posts. Alternate profiles use their authoritative owning account for membership; follows remain profile-based. Repository reads, query-builder search/trending, personalized feeds, and comment/resource parent reads use this boundary. Existing caller filters remain intersected with the policy.

Socket subscriptions and each content delivery reauthorize against the owning service with verified identity and bounded timeouts. Denials or lookup failures fail closed. Relationship, membership, community/privacy, deletion and restriction mutations invalidate active clients with an empty event. Multiple tabs are tracked independently. OT feed/direct-post consumers clear stale content, cancel pending reads, reload scoped state, and reject late results from the previous authorization state. Reconnect clears cached state and subscriptions are checked again.

Attachment/component/vote/comment reads resolve the actual owning parent rather than treating a missing scalar parent ID as an unrestricted lookup. Content-returning comment/vote creation checks parent access. Comment edits now use the owning update payload, receive an explicit success acknowledgment, invalidate active content, and return a fresh viewer-scoped comment. Broader write ownership and asset-byte authorization remain RR-08.

Changed projects: `social`, `gateway`, `client-interface`, `client-interface-e2e`. No shared library, schema, or migration changed. GPT-6-Luna supplied mapping, implementation, independent verification and adversarial review; the root completed browser evidence and bounded follow-up repairs. Work stayed in the current checkout.
