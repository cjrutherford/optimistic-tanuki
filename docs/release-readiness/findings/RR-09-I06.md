# RR09-I06 — Exact post search filtering

**Status:** ACCEPTED — bounded exact-ID search repair (2026-10-11).
**Position:** Completed after RR09-I05 and before RR09-V01 / RR-10.
**Owner:** `apps/social/src/entities/post.entity.ts` (`postSearchDtoToFindManyOptions`) and the owning social API/service regression tests.

## Finding and repair

RR09-I05's controlled community-post probe used an exact `SearchPostDto.id` to read back its fixture. The DTO accepts an optional UUID `id`, but `postSearchDtoToFindManyOptions()` did not map it to TypeORM's `where` criteria. Community-constrained reads could therefore return multiple rows and could not establish exact identity.

The mapper now sets `where.id = searchDto.id` when an ID is supplied. Existing `communityId` / `communityIds` precedence and all app-scope, visibility, and viewer authorization behavior remain unchanged. The social controller applies `visiblePostWhere()` after mapping; the regression confirms the exact ID and other criteria persist through all six existing public, community, follower, and owner branches.
