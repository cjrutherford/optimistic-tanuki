# RR09-I06 — Exact post search filtering

**Status:** PLANNED — source and API mapping confirm an exact-ID search contract defect; implementation and live verification have not started.
**Position:** After RR09-I05 and before RR09-V01 / RR-10.
**Owner:** `apps/social/src/entities/post.entity.ts` (`postSearchDtoToFindManyOptions`) and the owning social API/service regression tests.

## Finding

RR09-I05's controlled community-post probe used an exact `SearchPostDto.id` to read back its own fixture. The DTO accepts an optional UUID `id`, but `postSearchDtoToFindManyOptions()` does not map that property into its TypeORM `where` criteria. The mapper does honor `communityId`, which constrained the probe to the intended community but still returned multiple posts; an exact-ID lookup therefore cannot establish which row was read and can select an older post. This is a source-confirmed API contract defect discovered during a release audit, not an I05 contrast repair.

Keep the finding bounded to exact post filtering. Preserve existing community, app-scope, visibility, and authorization behavior; do not broaden the search API or change privacy policy as part of this checkpoint.

## Required repair and acceptance

- Map a valid `id` to an exact post criterion in the existing search mapper.
- Add focused mapper/service/API regression coverage for exact-ID match, unknown-ID empty result, and combined `id` + `communityId`; assert the exact result and that a mismatched community does not return the post.
- Preserve existing non-ID search criteria and authorization/scope behavior with regression checks.
- Verify the owning HTTP/API read returns the exact intended post and an unknown ID returns no post; use a narrowly journaled synthetic owner fixture and remove it through the supported owner API with exact readback.
- Run affected tests/lint, the full development build, the approved stack refresh and independent review. Record any checks not run.

RR09-I06 is required before RR09-V01. RR-09 remains GAP FOUND until I05, I06, and V01 all pass; no broader release acceptance is implied.
