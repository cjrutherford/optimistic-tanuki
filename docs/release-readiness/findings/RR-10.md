## Confirmed source finding

### RR10-F01 — authenticated media retrieval rejects objects above 25 MiB and materializes whole objects

**Severity:** P1 — required large-media capability and bounded-resource behavior are missing.
**Evidence:** `apps/assets/src/app/internal-media.service.ts` rejects stored data above 25 MiB plus 64 KiB, calls `readAssetContent` with that cap, buffers the entire authenticated plaintext, and only then slices the requested byte range. `libs/storage/src/lib/local-storage.ts` decrypts a complete envelope into a `Buffer`. `libs/storage/src/lib/s3.service.ts` concatenates all response chunks into a `Buffer`. `libs/storage/src/lib/envelope-encryption.service.ts` uses one AES-256-GCM authentication tag for the full envelope, so the current format cannot safely release unauthenticated partial plaintext before final tag verification.

**Upload boundary:** `apps/assets/src/app/app.service.ts` materializes content or reads `sourcePath` using `fs.readFile` before validation/scanning. Video has no `maxSizeBytes` in `FileValidationService`; `VirusScanService` currently rejects buffers above its configured scan limit (25 MiB by default), which is after materialization. Do not describe video upload as unlimited or large-media ingestion as accepted. The supported upload/read limits and scanner strategy must be explicit in I01.

**Transport considerations:** `apps/gateway/src/controllers/asset.controller.ts` fetches internal media without an abort signal or deadline and pipes the response. `apps/assets/src/app/internal-media.controller.ts` also pipes directly. Any verified spool or chunk-auth design needs bounded disk/memory, downstream cancellation, backpressure, abort/error cleanup, and protection against serving bytes before the applicable authentication check completes.

**Required repair and proof:** RR10-I01 in the execution plan. Prove authorization before plaintext, full and range byte fidelity, correct plaintext lengths, tamper/wrong-key fail-closed behavior, bounded memory/disk, cancellation and cleanup, explicit supported limits/actionable errors, and production-like key/scanner configuration. Regress the TS listing image flow and shared OT media consumers. No live large-file attempt was run during mapping.

**Targeted verification already run by the independent verifier:** `NX_DAEMON=false NX_ISOLATE_PLUGINS=false /home/cjrutherford/.local/share/pnpm/pnpm nx run assets:test --testFile=src/app/internal-media.service.spec.ts --runInBand` passed 1 suite / 14 tests (Nx run `8ovzCK4VEe`, 8.9 seconds). `NX_DAEMON=false NX_ISOLATE_PLUGINS=false /home/cjrutherford/.local/share/pnpm/pnpm nx run storage:test --testFile=src/lib/local-storage.vault.spec.ts --runInBand` passed 1 suite / 26 tests (Nx run `jvUlPBYdvq`, 7.4 seconds). These are unit evidence only; large-object, S3, abort, memory, upload, and live browser acceptance remain NOT RUN.
