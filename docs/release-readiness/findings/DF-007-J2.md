# DF-007 J2 — Authentication database capture

**Status: locally verified owner-reader component.** Authentication can now capture its eight retained database sources through a separate transaction-consistent stream. The existing five-participant previews and job runner remain unchanged. This component is registered in Authentication but is not yet consumed by the export job runner. No account download, deletion or user-facing control is enabled. Item 1, DF-007 and RR-11 remain open.

The reader validates the current session against the requested account and app. It reads one PostgreSQL repeatable-read, read-only snapshot, using pages of at most 250 rows and explicit source exhaustion. A null initial cursor includes the minimum UUID; there is no 1,000-row scan ceiling. Selected text/JSON/key sizes and serialized pages are bounded; an oversized or malformed record fails the capture instead of producing a truncated success. The capture has a cooperative 45-second deadline, statement timeouts and an abort signal passed to its awaited sink. Hard cancellation during unresponsive connection acquisition is not established.

The stream covers identity/security state, verified public-key linkage, retained sessions, OAuth links, authentication actions, policy notices, export-job history and guardian permissions. [Field dispositions](../evidence/df-007/authentication-owner-fields.json) distinguish retained data, derived state, credentials, counterpart information and operational fields. Account-wide export includes the requester's safe history across app scopes; session authorization and individual job access remain app-bound. Guardian records expose only the requester's role-specific fields. Matching email-only or conflicting links fail closed; unrelated unlinked requests do not block the capture. This is database ownership coverage, not acceptance of the wider store inventory.

The terminal proof follows transaction commit. A shared verifier checks account/capture identity, contiguous pages, monotonic keys, source order/exhaustion, exact counts and checksum. It rejects further input after failure or completion. Its injected digest avoids a Node dependency in the browser-shared Models barrel. A consumer must await the producer's successful return and discard staging on any error, even if it received a terminal envelope.
