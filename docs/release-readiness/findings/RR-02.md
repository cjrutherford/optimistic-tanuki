## Registry and authentication boundaries

The list's app destinations are dynamically resolved from `/api/registry/apps`. No production origins are hard-coded into application code. Existing curated directory membership remains unchanged; registry values decide whether a public app destination exists and where it points. Unit coverage verifies a published path such as `/towns/` survives resolution, and browser fixtures vary destinations to the two locally running applications. These fixtures establish frontend behavior, not live registry availability.

The operator supplied the production registry dated 2026-09-22 and confirmed the account model: **shared credentials, separate sign-in sessions**. The gateway's browser-session cookie options are host-only, HttpOnly, SameSite=Lax, path `/`; the clients request their own same-origin session endpoint. Two domains on one machine do not by themselves share browser cookies. No seamless-session handoff is required or advertised by this slice. RR-03 still owns account/session lifecycle and safety validation.
