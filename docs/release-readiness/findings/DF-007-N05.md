# N05 — OT/TS media-store deletion contracts

**VERIFIED locally for the stated storage boundary.** This does not complete account deletion, artifact downloads or deployed-storage qualification. See the [receipt](../evidence/df-007/checkpoint-n05.json) and [inventory](../evidence/df-007/n05-media-store-inventory.json).

The remote Assets adapter previously sent an ordinary S3 DeleteObject request. In a versioned bucket that can leave old encrypted versions and delete markers. It now uses a bounded exact-key purge that lists versions and markers, deletes explicit version IDs, rejects page/version limits and partial failures, then independently lists and HEADs the key before acknowledging absence. Prefix neighbors are never selected. No governance/legal-hold bypass is sent; retained versions must produce a visible failure, not a successful deletion receipt.

The existing N01 Assets lifecycle still reserves and locks writes, retains pending-delete metadata when storage removal fails and retries cleanup. Its accepted real local-adapter proof is reused. No new create-video producer was invented: neither scoped client has one in the accepted N01 map. This does not assert that deployed volumes, operator backups or all legacy video data are absent.

A fresh real MinIO fixture used the actual S3 SDK, S3 service and NetworkStorageAdapter. Two encrypted versions and a delete marker were present. A private HTTP proxy returned 503 for delete batches: failure remained visible and the versions remained. After removing that transport fault, retry and an idempotent second retry passed; independent list readback found zero selected versions/markers. A separate prefix-neighbor object remained decryptable. That neighbor proves object/key isolation, not a second account's authentication; upstream identity/ownership remains the prior Auth/Profile/Assets boundary.

The fixture was built from the [official tagged source](https://github.com/minio/minio/tree/RELEASE.2025-10-15T17-29-55Z) after public image pulls and the official binary endpoint were unavailable. Source SHA and binary digest are recorded. It listened only on loopback with disposable credentials; its server, proxy and temporary data directory were removed. No workspace dependency, deployed storage or shared container was changed.

The key inventory is explicit: each encrypted envelope holds its own wrapped data key. Deleting all versions removes those application-accessible envelopes; the shared KEK remains available for unrelated objects. This is not destruction of the shared KEK, a forensic disk-block wipe or a claim about copied envelopes/backups. Those limits must survive launch wording and operator qualification.

Two earlier SDK fixture failures were corrected and retained in the receipt.
