## Audit plan

The audit covers user-visible critical paths, not only public entry pages. OT coverage includes registration/sign-in, feed tabs, post/comment composition, profile/settings, community browse/join/manage, reporting, and messaging. Towne Square coverage includes locality/community browsing and joining, listing creation, and seller contact. A flow is included only where the current app and stable test fixture make it reachable; any exclusion is recorded with its reason. Forge of Will and Business Site remain shared-library regression targets only if this audit changes a shared library.

The live-browser viewport matrix is 320×740, 375×812, 768×1024, and 1280×633, with 1440×900 as the desktop reference. Manual keyboard checks advance focus with repeated Tab/Shift+Tab and activation keys, verify the actual active element and visible focus, and exercise real report/manage dialogs for trap and restoration. Checks include form labels and field errors; icon-only names and live announcements; computed contrast in supported light/dark themes; actual rendered decorative/personality behavior under `prefers-reduced-motion: reduce`; touch target size and floating-tag overlap. Automated axe scans run on representative route and dialog states where the checked-in toolchain supports them. Hidden or zero-sized controls are excluded from touch measurement; each exclusion is recorded.

Before each live run, record port readiness and current stack state. Use system Chrome and the checked-in Nx E2E target with live-stack skip flags, one worker, and no teardown of shared services. Use controlled test accounts/owner configuration, retain only accounts explicitly marked retained, and journal narrowly scoped fixtures with exact cleanup. Preserve the DB, object-store assets, encryption keys, and running services. T3 preview status/open already reported that no preview host is available; do not retry it or substitute another preview mechanism.

## Fresh public-matrix observations (partial)

- No horizontal overflow was recorded, and no visible measured interactive target was below 44px in either dimension. The HAI tag bounds did not intersect `<main>` in any sampled state. These measurements do not replace keyboard or touch-path checks.
- Emulating dark media left the active app theme and body colors unchanged (`personality-soft-touch`, foreground `rgb(17, 17, 19)`, background `rgb(247, 244, 238)`). This is not a supported-theme contrast result.

Both harness defects were corrected; the collector now uses keyboard activation and route-specific readiness. No result from the early failed checks is product evidence.

- Axe found serious `color-contrast` violations in 25 states. `/cities` filter chips render `#626ca2` text on `#dedbdd` at 3.65:1 (expected 4.5:1) across all ten sampled cells. `/login` and `/register` links render at 4.36–4.48:1 on `#f7f4ee` in 15 sampled cells.
