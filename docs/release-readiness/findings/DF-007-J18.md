# DF-007 J18 — Verify selected-profile ownership before minting sessions

**Status: locally verified bounded Auth/Profile slice.** Explicit profile selections now require an ownership proof before Authentication signs a JWT or inserts a session. DF-007 and RR-11 remain open.

## Behavior

A shared verifier covers password Login, internal Issue, email-action login and OAuth session issuance. It uses the established account identity, canonicalizes UUIDs, requires an exact scoped Profile reply with `owned: true`, and bounds the RPC wait to three seconds. Foreign, missing, malformed and unavailable selected profiles fail closed. Profile returns only canonical IDs and an ownership boolean from a primary-key existence query with a case-insensitive legacy account-ID comparison; it does not call Auth validation. The canonical types remain in Profile contracts and are re-exported through the shared constants boundary.

Missing selections retain profileless behavior, and deferred login creates no session. Email-action ownership denial leaves the one-time action usable. Existing app-scope and guardian checks remain in place; this slice adds no guessed app alias rules or continuous revalidation of previously issued sessions. No schema, migration or UI change was needed.
