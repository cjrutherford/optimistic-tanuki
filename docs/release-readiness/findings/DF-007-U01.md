# U01 — Account export controls

Status: **VERIFIED LOCAL**, 2026-10-26. Classification: **COMPLETE-local**.
Scope: OT `client-interface`, TS `local-hub`, and their required shared services.

The existing OT Settings and TS My Account pages now mount one shared
account-rights panel. Authenticated Gateway routes create/read/retry/cancel the
real export job, reject a stale expected account, and return minimal status.
Download requires a complete, available artifact and uses a native attachment
stream after a readiness check. Angular does not buffer the archive.

The private U03 run drove both rebuilt applications through real session
validation, guarded Gateway HTTP, Auth TCP and all twelve owners. OT downloaded
75,776 bytes and TS 76,288 bytes. An independent TAR parser checked the app/account
manifest and every one of the twelve owner-stream sizes and SHA-256 digests.
Stale-account preparation was rejected with HTTP 409 in both apps. Earlier
failure runs showed a failed capture with no ready download instead of false
completion. Focused checks cover job scope, retry/cancel, stale responses,
expired availability and download errors.

This proof exposed an anonymous media descriptor regression: unbounded reads
started at EOF after staging. The owning real-file test reproduced the empty
read; defaulting each read to byte zero fixed it. Nine owning tests pass,
including full/range/full reads, while read leases and cleanup remain enforced.
The final coupled run includes actual decrypted PNG media export.

Evidence: [U01 receipt](../evidence/df-007/checkpoint-u01.json) and
[U03 finding](./DF-007-U03.md). Native downloads become user-held copies and are
not promised erased by later account deletion. Provider, backup, deployment,
full login journeys and remaining R/X qualification stay separate.
