# DF-007 J9 — Assets snapshot transport and Authentication integration

**Status: locally verified bounded J9 slice.** Assets exposes a leased, bounded snapshot handle over internal RPC, and Authentication pulls that snapshot into a verified local spool during the account-export job. This slice does not complete DF-007 or RR-11.

## Implemented behavior

The Assets snapshot binds its capture to the supplied Profile snapshot handle, capture ID and timestamp. Authentication keeps the Profile capture open until Assets capture cleanup finishes, then releases Profile. During failure or shutdown, Assets waits for the actual owner capture promise to settle before resolving the open operation and releasing its opening slot or byte reservation; the generic spool's abort race alone does not acknowledge owner cleanup.

The Assets registry limits opening or published captures to two, reserves up to 256 MiB per capture within a 512 MiB aggregate budget, expires published handles after 120 seconds, and caps reads at 64 KiB. Capture has a 45-second deadline. Cleanup failures keep the entry charged and inaccessible while cleanup is retried. Lease checks fence open and read operations. Exact-scope release remains available after lease/session revocation so stale captures can be released without returning account data. RPC failures are converted to stable errors; the capture grant and session token are not stored in the snapshot registry.

The transport preserves J8's captured metadata and actual authenticated plaintext media bytes in the verified Assets spool. J8's media limits remain 64 MiB per file and 128 MiB per capture; encrypted-storage authentication, signature checks, chunking and cleanup are described in [J8](./DF-007-J8.md). The service stages the complete snapshot and verifies the descriptor, digest, source counts and terminal proof before returning a local handle to the job. Job cleanup closes Assets resources before the retained Profile capture.

No schema or migration was added. This slice does not provide the final account artifact, durable media storage, deletion, shared UI, other owner captures, video support or production qualification.

It also verified that Profile's parent capture remained usable through an Assets container restart, the prior Assets handle did not survive restart, and recapture produced a new Assets snapshot. Asset-table readback matched its pre-run fingerprint, and independent readback found no fixture users, jobs, Assets rows, guardian activity, Profile rows or temporary relations. Authentication, Profile and Assets spool descriptor checks were zero before/after; media fixture files were cleaned, and the private project ended with zero containers, networks and volumes.

The first runtime attempt stopped because the private database bootstrap omitted the Assets database; it did not reach the tests. The fixture setup was corrected to include the additional database. Attempt 2 used newly built Authentication and Assets images, reused the previously verified J6 Profile and other dependency images, and did not modify production images or services. Cancellation drain after a generic spool abort is proven by the focused unit test only; this runtime did not exercise that cancellation path. The runtime is bounded private-stack evidence, not release or production qualification.
