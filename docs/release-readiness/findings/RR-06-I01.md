## Bounded media and operator prerequisites

Authenticated local-media reads support **25 MiB plaintext + 64 KiB envelope overhead**. The adapter opens one `O_NOFOLLOW` descriptor, validates regular-file size before allocation, reads a bounded buffer and detects growth/change, then uses the existing decryptor. Ranges and lengths use authenticated plaintext. Oversize returns 413; missing/wrong keys and tampering fail closed. No raw ciphertext fallback remains. Larger media delivery requires RR10-I01 before release.

Upload proof used a generated test key paired with an isolated `rr06_i01_asset_probe_data` volume, preserving the original asset volume and its key. At closeout the test volume had zero files; the original asset service/storage configuration was restored, and the disposable volume and permission-restricted key override were removed. Production-like upload acceptance still requires an operator-provisioned stable `VAULT_STORAGE_KEK`, retained with its encrypted storage, and a real scanner. A test key must never be applied to existing encrypted assets. The original configuration lacked the key during preparation; this repair does not silently replace it.
