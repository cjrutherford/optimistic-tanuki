# A06 — artifact expiry and cleanup

**VERIFIED LOCAL OT/TS, 2026-10-24.** Local filesystem custody and the internal account-purge hook are qualified. D00 still owns permanent account quiescence and D01/D26 own the wider account/identity lifecycle.

Artifacts expire after 24 hours; current session and descriptor checks deny reads at the deadline, independently of the cleanup timer. Startup and minute sweeps process bounded batches under locked ledger rows. Cleanup invalidates verified download handles, removes both published and interrupted encrypted files, syncs the directory and independently checks absence before clearing private custody metadata. Failed cleanup keeps the descriptor and cleanup-pending state for retry. Shared wrapping keys remain available; the removed files contain their own wrapped data keys.

Reservation and final publication use the same current-job row lock as purge. Pending names are tied to the server-selected artifact UUID. A delayed writer cannot create a new staging or final file after its intent/lease is removed. Recovery can authorize deletion of an incomplete encrypted file from its exact stored intent; it does not depend on a live user session.

Five retention tests, eleven real-filesystem store tests and the migrated PostgreSQL fixture passed. The PostgreSQL cases cover expiry/readback, injected removal failure/retry, live-lease/nonce boundaries, and a writer blocked before publication: both staged and final names are absent before cleanup acknowledges, and remain absent after that writer resumes. A07 verified the actual scheduler, denied expired reads, empty artifact directories and restored databases.

The internal account hook fences selected running jobs and preserves custody on failure. It is not a public deletion API or proof of D00. Readback covers the qualified local namespace; deployment snapshots, backups and operator key custody remain separately owned external qualification.
