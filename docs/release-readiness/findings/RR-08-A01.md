# RR08-A01 — Classified image audience authorization

**Date:** 2026-10-07. **Baseline:** `bca19ed43`. **Status:** ACCEPTED — bounded repair, independently verified and reviewed. Full RR-08 remains IN PROGRESS.

## Scope and design

Close the required private classified-image URL authorization gate. The source trace is gateway `GET /api/asset/:id` → assets internal-media → encrypted storage. The gateway previously passed the asset ID to the internal service without checking content audience. Classifieds listing reads already enforce scope/private-community membership, but image reads bypass that policy. The controlled baseline below now confirms anonymous private-image delivery; source tracing alone was not treated as reproduction.

Use a durable asset audience association so a private upload is protected before the listing is saved and does not become public when an image reference is removed. Bind upload actors to the verified session, validate target-community scope/membership, and recheck current audience/access for each read. Resolve legacy classified references through their owning service; deny inaccessible or ambiguous private associations. Reject attachment that would broaden an image's audience. Preserve public media positives, authenticated plaintext ranges and owner access consistent with RR06-I01. Private responses must not be shared-cacheable. Dependency errors must fail closed.

Affected owners: gateway, assets, classifieds, shared asset/classified contracts, TS upload callbacks and focused E2E. A schema change must use the owning assets Nx migration-generation target, followed by generated SQL review, fresh-database migration/reversibility checks and the migration validator. No shared database reset, production key replacement or worktree.

**Additional source finding — public server-file import:** The HTTP upload DTO accepted `sourcePath`, which reached raw server `fs.readFile`. The public gateway now rejects that field; trusted internal video-processing RPC imports retain it. No private server file was read for validation; the fixture is harmless. Final live HTTP probe returns 400 for the harmless server-file fixture; trusted RPC imports remain available.

**Additional repairs:** Upload identity is bound to an owned profile and the authoritative community scope. Private uploads receive an audience before saving a listing; the detail/edit callback also carries the owned listing context, allowing an owner who has left the community to edit their own ad without opening other members' media. Legacy references are accepted only for the persisted media owner. Removing a reference does not remove its private restriction. The final browser run exposed a shared classified form sending immutable `communityId` during editing (HTTP 400); the form now sends editable fields on updates and retains community context on creation. A failing regression test preceded that correction.

## Composition and trust boundaries

Asset routes now require assets/authentication/permissions **and profile/social/classifieds** to establish ownership, current audience and legacy policy. A partial gateway composition omitting these dependencies omits the asset controller; it must enable the complete authorization closure to serve media. This deliberate fail-closed route policy does not silently serve unknown legacy images publicly. Full-registry public media positives are required by this checkpoint; no independent minimal-composition runtime is claimed.

Internal media retains its service-token check and requires a fresh asset-bound signed authorization assertion for audience-associated assets. Asset RPC imports/retrieval remain trusted service-to-service interfaces for video processing. This is not proof of external TCP/firewall isolation; the full RR-08 deployment/network boundary remains open. Legacy private associations are accepted only when the listing profile matches the persisted media owner; a borrowed public/remote image cannot acquire a new private audience from another author. Already-persisted private associations remain enforced independently of later references.
