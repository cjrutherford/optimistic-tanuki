## Contract implemented

The gateway now binds the deletion request to the authenticated `userId`, looks up the target profile, and requires an exact match between its app scope and the request's app scope. A missing target returns 404. A missing/unknown owner, foreign owner, wrong app scope, global profile, or null-scope legacy profile returns 403. A lookup transport failure returns a generic 502 without forwarding private profile details. For an owned profile in the current app scope, the gateway returns 501 with a stable unavailable message because the profile service has no delete handler and dependent-data retention has not been approved.

The route source contains no `ProfileCommands.Delete` send, and unit assertions verify no Delete RPC is emitted across tested branches. The live HTTP harness did not instrument the RPC stream. The route does not grant a moderator or platform-owner bypass: the handler checks `userId` ownership after the permission guard. Global and null-scope profiles, including RR09-I04's retained synthetic global profile, remain protected. Existing profile reads and updates were not changed.
