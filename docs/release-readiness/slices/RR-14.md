### Questions answered

- The current system addresses federation-ingress abuse and local moderation risk, not global user/content reputation or moderator trust.
- Scores are a local instance's opinion of an actor and/or domain. Signed evidence can arrive from peers; scores are not shown to be portable global facts. Local vouches influence recommendations.
- Inputs include local/inbound reports, signed expiring attestations and revocations, local vouches, and explicit operator mutations/blocks.
- Admin-gated endpoints expose evaluations and audit records. Explanatory reasons, reversible recommendations, decay, and operator overrides exist in source. An affected-user appeal/contest flow and tamper-proof audit guarantees were not established in the reviewed corpus.
- Report deduplication/caps and issuer/domain/evidence weighting mitigate some brigading, but do not prove Sybil resistance, independence, or non-collusion. Retaliation, false evidence, and collateral domain effects require adversarial evidence.
- Report-derived recommendations can be applied as bounded score penalties; some trust recommendations remain advisory, while the durable trust bridge applies selected non-observation penalties. These controls are not accepted production behavior.
- The durable service has database entities, migrations, policy versioning, audit/evaluation rows, idempotency, and API surfaces. A legacy in-memory evaluator remains in the codebase; the older root simulator is a separate mock and is rejected for reuse.
- The platform separation is visible in the Nx library architecture. This audit does not authorize direct code transfer while rights/ownership are unresolved; independently implementing selected concepts is a separate product/architecture choice.
- The reviewed code stores identity, evidence hashes, provenance, reasons, and decision metadata. Retention, deletion, export, notice, and reporter confidentiality require explicit policy and verification.
- Federation means local scores consume peer-issued evidence; issuer signatures establish origin, not truth. Existing actor-only evaluation for identities without a host does not establish a stable universal identity model.
- No per-community opt-out/policy boundary or affected-user appeal workflow was established. Operator blocks and audit are present, but human override does not itself satisfy fair process.

### Reuse, adapt, rewrite, reject

- **Adapt as design concepts:** actor/domain separation, bounded reversible decisions, evidence expiry/revocation, idempotency, and auditability. No Retumbl code is approved for transfer.
- **Rewrite only after product approval:** a narrow OT-local moderation evidence workflow with explicit scope, notice, contest, privacy, human review, and opt-out rules. No implementation slice is created now.
- **Reject:** the seeded/random in-memory simulation, score-based vouch bypass as a default rule, direct global/shared-HAI or TS scoring, and any unlicensed source/schema transfer.

Placement recommendation: keep separate/deferred. If OT adopts anything later, evaluate local contextual moderation first; do not treat popularity or social endorsement as authority. This is not an ADR or owner-approved placement decision.
