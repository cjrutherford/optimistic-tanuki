Highest-impact findings

P1 — Forecast is useful context, not an affordability answer

Slice B calculates a 90-day daily balance from active workspace accounts, active recurring credits/debits, and monthly funded-goal allocations. It intentionally does not reserve spending categories, predict variable transactions, factor debt terms, reconcile actual postings, or recommend a tradeoff.

User consequence: a user can see whether scheduled inputs trend the balance up or down, but still cannot ask whether a goal is safe to approve or what must change to fund it.

Guidance: Slice C adds approval, a preview, and a linked recurring/budget instruction.

P1 — “Scenarios” cannot model an outcome

Each scenario stores a summary and JSON records with string deltas and an impact label. There is no date range, numeric value, probability, account/category target, dependency graph, baseline snapshot, or recomputation. Calling this “what-if modeling” overpromises the implemented capability.

User consequence: a scenario is a labeled note, not evidence for a financial decision.

Guidance: Slice C defines the typed, approved directive and preview boundary before scenarios can safely drive accounting work.

P1 — The information architecture promises a closed loop it does not deliver

The Plans page says operational money work and forward plans “stay connected”; the Overview shows workspace balances. But plan entities have no ledger relation other than tenant/workspace context, and no action turns a plan decision into a budget, recurring item, transfer, or review task.

User consequence: users must manually translate decisions into day-to-day accounting work, duplicating context and losing traceability.

Guidance: Slice C is the explicit execution bridge and must preserve a reversible audit link.

P2 — Release checks are broader than the product slice

The affected graph is broad in this shared branch, so CI plans a large Docker image matrix. The directly affected Gateway, Finance, and Fin Commander images build successfully, but a clean remote PR run is still the authoritative proof for the complete matrix.

Guidance: record the exact matrix evidence and republish verified hosts at closeout.

P1 — Entity collaboration is proven in API tests but not yet a usable product workflow

Member lifecycle routes and five-account isolation are valuable foundations. The user-facing Entity members route must make selection, roles, removal, and errors understandable before households or teams can confidently collaborate.

Guidance: Slice D exposes add, role change, removal, denial, and five-user browser proof.

P2 — Visual credibility is ahead of operational credibility

Cards, “live” language, and command-oriented labels create an expectation of calculated advice. The actual inputs are mostly manually authored fields. The unauthenticated live session also logged a 7:1 contrast warning for the Professional theme and fallback fonts.

Guidance: keep visual claims bounded until a focused UX/accessibility slice supplies live evidence.

Create an approved, tenant-scoped recurring funding instruction from a goal. Preserve an audit link both directions and do not mutate a ledger or account balance.

Slice D — Collaboration UI
