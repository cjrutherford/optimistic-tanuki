Highest-impact findings

P0 — Forecast is useful context, not an affordability answer

Slice B calculates a 90-day daily balance from active workspace accounts, active recurring credits/debits, and monthly funded-goal allocations. It intentionally does not reserve spending categories, predict variable transactions, factor debt terms, reconcile actual postings, or recommend a tradeoff.

User consequence: a user can see whether scheduled inputs trend the balance up or down, but still cannot ask whether a goal is safe to approve or what must change to fund it.

P0 — “Scenarios” cannot model an outcome

Each scenario stores a summary and JSON records with string deltas and an impact label. There is no date range, numeric value, probability, account/category target, dependency graph, baseline snapshot, or recomputation. Calling this “what-if modeling” overpromises the implemented capability.

User consequence: a scenario is a labeled note, not evidence for a financial decision.

P1 — The information architecture promises a closed loop it does not deliver

The Plans page says operational money work and forward plans “stay connected”; the Overview shows workspace balances. But plan entities have no ledger relation other than tenant/workspace context, and no action turns a plan decision into a budget, recurring item, transfer, or review task.

User consequence: users must manually translate decisions into day-to-day accounting work, duplicating context and losing traceability.

P1 — Entity collaboration is proven in API tests but not yet a usable product workflow

Member lifecycle routes and five-account isolation are valuable foundations. The user-facing Entity members route must make selection, roles, removal, and errors understandable before households or teams can confidently collaborate.

P2 — Visual credibility is ahead of operational credibility

Cards, “live” language, and command-oriented labels create an expectation of calculated advice. The actual inputs are mostly manually authored fields. The unauthenticated live session also logged a 7:1 contrast warning for the Professional theme and fallback fonts.

Recommended product slices

Slice A — Funded goal directive · delivered

Goals now select a Finance-tenant active account. Finance validates scope and returns its balance, remaining target, inclusive months remaining, overdue state, and a ceiling-rounded required monthly contribution. The UI renders this source-backed directive without moving money.

Verified: service, controller, component tests; scoped build/lint; local Finance migration applied. The broader browser journey remains blocked by unrelated budget-row instability before it reaches the new goal assertion.

Slice B — Deterministic cash-flow projection · delivered

Finance exposes a tenant-scoped, read-only 90-day projection that starts from active accounts in the plan workspace, schedules active recurring credits/debits and funded-goal allocations, and returns dated balances and source events. Cash Flow presents its calculation date, opening-to-projected balance, event count, and an explicit no-affordability disclaimer.

Verified: Finance engine and controller tests, Gateway forwarding test, Fin Commander component test, scoped build, restart, route registration, and lint for all affected projects.

Slice C — Execution bridge

Let an approved directive create or revise a budget, recurring transfer, or review task. Preserve an audit link both directions and require confirmation for ledger-affecting changes.

Acceptance: approving a directive creates a linked recurring funding instruction without silently moving money.

Slice D — Collaboration UI

Wire the verified membership API into Entity members: searchable Finance-scoped profiles, role change, remove, clear owner-only states, and revocation messaging.

Acceptance: an owner can grant/revoke a member in the UI and both sessions visibly receive the expected access outcome.

Slice delivery record

  • Slice A: goals select a Finance-tenant active account; Finance validates scope and returns a source-backed monthly directive. Legacy goals without a funding account remain readable without a directive.
  • Slice B: shared contracts, Finance projection service/handler, Gateway route, Fin Commander API client, and Cash Flow summary now form the read-only forecast path. The route is registered as GET /api/finance/fin-commander/plan/:planId/projection.
  • Authenticated browser proof: the canonical Chrome journey now passes without retries against the local Docker stack. It registers and logs in a fresh user, creates finance data and a plan, receives the protected projection with 200, renders the forecast/directive, and commits an import with no browser console, page, request, or failed-response diagnostics.
  • Test-stability repair: AG Grid virtualized rows do not expose accessible names. The canonical journey now scrolls each grid into view and asserts visible cell content; stale plan-form and plan-scoped-goal endpoint assertions were also aligned to the current UI/API contracts.
  • Projection limits: monthly goal allocations are scheduled from the calculated directive; the current UI intentionally summarizes the forecast rather than rendering its event ledger or balance chart. Forecast inputs are current state, not a preserved scenario baseline.
